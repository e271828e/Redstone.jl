1235	### D-039 — Assembly declaration is type-based
1236	
1237	**Status.** ratified
1238	
1239	**Position.** Assembly declaration is type-based: plain struct, children =
1240	component-typed fields, parameters = the rest; `connections`
1241	mandatory-even-empty as the kind marker; one root `AbstractComponent`, kind by
1242	declaration shape — the rule is total: `connections` marks an assembly, any
1243	leaf declaration (`init_*`, `workspace`,
1244	`input_types`/`output_types`/`local_types`, `events`, any
1245	stage/`f`/`g`/`project` method) marks a primitive, and declaring neither family
1246	is a build error naming both.
1247	
1248	**Spec.** [§8.5][s8-5], [§8.8][s8-8]
1249	
1250	**Rationale.** Recorded only through the rejections below.
1251	
1252	Annotation (2026-10-02): "per [§8.3][s8-3]" in the second rejection reads "per
1253	[§8.5][s8-5]", which states that class, this entry's kind, is implementation detail
1254	behind the contract.
1255	
1256	**Rejected.**
1257	- *Builder (`add!`/`connect!`):* dispatch type and structure recipe drift apart
1258	  — [§8.1][s8-1]'s disease at assembly scale; mutable declaration state; doesn't even
1259	  capture source locations.
1260	- *`AbstractAssembly` kind supertype:* single inheritance is spoken for by
1261	  domain hierarchies; kind is an implementation detail per [§8.3][s8-3].
1262	- *Kind inferred from field types:* heuristic where a declaration is wanted.
