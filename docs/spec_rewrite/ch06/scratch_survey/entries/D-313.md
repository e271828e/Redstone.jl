13121	### D-313 — Admit a library block by judgement against three guidelines
13122	
13123	**Status.** ratified
13124	
13125	**Position.** A block joins the standard library's inventory by judgement
13126	against three guidelines, none of them a requirement. It is domain-agnostic
13127	and generally useful; it has didactic value, as when it shows one framework
13128	mechanism in a simple form; and its implementation is difficult to get
13129	right. A listed block is built whenever wanted, with no demonstrating model
13130	required.
13131	
13132	- The inventory, its grouping and the Simulink mapping that prunes it live
13133	  in `companions/library_inventory.md`.
13134	- The library is the submodule `Redstone.Blocks`, `Group` included, written
13135	  against the extension-only surface as a user's component file is. A
13136	  workspace sub-package or a separate repository is an after-release
13137	  question.
13138	
13139	**Spec.** [§13.7][s13-7]
13140	
13141	**Rationale.** Simulink's base library is large because the diagram is its
13142	expression language, so `2u + 3` needs a Gain and a Bias. Here a stage body
13143	is Julia, and the same expression as a block costs a build entry, a cell, a
13144	gather and a scatter, and teaches the diagram-granularity style the design
13145	rejects. Sinks are the snapshot table and the log, a terminator is an
13146	unwired output, stop is a stop face, buses are structs, and zero-order hold
13147	and rate transition are the tiers. What is left is the group users lose
13148	time on in every framework: a limited integrator is a mode with two events,
13149	not a clamp, and a lag filter typed at `Float64` fails the first
13150	linearization. The guidelines say why those belong and a gain does not. A
13151	gain is domain-agnostic but teaches nothing and is one line of a stage
13152	body, while the limited integrator shows modes and events in their simplest
13153	form and is easy to get wrong. The guidelines are weighed, not satisfied one
13154	by one, and a block that plainly belongs is not argued into them. Whether a
13155	model already demonstrates a block is no condition. The library's first
13156	user builds what they want to play with, and the inspector's first examples
13157	need blocks before the example model exists. A submodule reaches `x_init`
13158	and its siblings by import, so the library exercises the surface a user
13159	extends instead of the package's internals, and the audit scopes its names
13160	as one group.
13161	
13162	Annotation (2026-10-08): stop is a stop request since [D-316][d-316], a `StopFlag`
13163	port, which the library spells `StopRequest`.
13164	
13165	**Rejected.**
13166	- *A Simulink-sized library:* most of it is one-line expressions, and the
13167	  cost model of [§9.7][s9-7] charges per component.
13168	- *Admission by framework mechanism, with a demonstrating model:* every
13169	  block needs framework knowledge to write correctly, so the mechanism half
13170	  excludes nothing by itself, and the demonstrating-model half parked every
13171	  candidate behind the example model.
13172	- *Strictly demonstrated need, unchanged:* argues every block of the second
13173	  tranche separately, with no principle to argue it by.
13174	- *A plain file inside the module:* every internal name in scope, so the
13175	  library stops testing the extension-only surface.
13176	- *A separate package now:* unused block types cost nothing at model build,
13177	  and the submodule scopes the audit as well; the split is an after-release
13178	  question.
