6094	### D-170 — Split assembly connections into child/input/output declarations
6095	
6096	**Status.** ratified
6097	
6098	**Position.** Assembly routing declarations renamed and split: `connections` →
6099	**`child_connections`** (strictly child-port → child-port, keeps the
6100	mandatory-even-empty assembly kind-marker role); `exports` **splits by
6101	direction** into **`input_connections`** (face => internal input path or
6102	tuple-of-paths fan-out; entry spelling unchanged) and **`output_connections`**
6103	(internal source path => face, now flow-ordered); direction is *declared by the
6104	method*, [D-041][d-041]'s endpoint derivation becoming a cross-check with a sharper
6105	error and the mixed-entry class inexpressible; face-name uniqueness spans both
6106	boundary declarations; one invariant spans all three: every pair's arrow points
6107	the way the signal flows, left = producer or entry point, right = consumer,
6108	every right side fed exactly once.
6109	
6110	**Spec.** [§3.3][s3-3], [§6.1][s6-1], [§6.2][s6-2], [§11.3][s11-3], [§8.1][s8-1], [§8.2][s8-2], [§8.5][s8-5], [§8.6][s8-6], [§8.8][s8-8], [§9][s9], [§13.3][s13-3]
6111	(swept)
6112	
6113	**Rationale.** Supersedes [D-041][d-041]'s single-method shape; [D-039][d-039]'s marker role
6114	transfers. Motivation: the old `exports` held two opposite flow directions in
6115	one list — spelling-uniform (face on left) at the price of flow-uniformity, and
6116	any single mixed-direction list must sacrifice one.
