13012	### D-311 — Fold the summing junction and the Bool gates into one generic `Junction`
13013	
13014	**Status.** ratified
13015	
13016	**Position.** The library's N-to-1 blocks are one leaf, `Junction{In, Out, N, F}`,
13017	whose instance holds the fold.
13018	
13019	- `u_types` is `(in1 = In, …, inN = In)`, `y_types` is `(out = Out,)`, and
13020	  `y_direct` applies the instance's `f` to the inputs in positional order.
13021	  `In`, `Out` and `N` are spelled; `Junction{In, Out, N}(f)` infers `F`.
13022	- `SumJunction{V, N}`, `Or{N}` and `And{N}` are constant aliases at `+`, `|`
13023	  and `&`, each with a zero-argument constructor. `Not` is not admitted.
13024	- The type parameter is the nominal type, `SumJunction{Wrench{Float64}, 3}`,
13025	  never an unparametrized constructor. [§6.2][s6-2]'s `W{Float64}` form falls with
13026	  [D-263][d-263].
13027	- Every library block's output port is `out`. The junction's `Σ` falls.
13028	
13029	**Spec.** [§6.2][s6-2], [§8.2][s8-2], [§8.5][s8-5], [§13.5][s13-5], [§13.7][s13-7]
13030	
13031	**Rationale.** A gate exists for its consumer, which wants one consolidated
13032	`Bool` input instead of several and the operation inside. That is the summing
13033	junction's shape with another fold, so one leaf covers both, and a custom
13034	fold, a weighted blend or a mass-properties composition, is [§6.2][s6-2]'s arbitrary
13035	stage-2 aggregation written at the site. `In`, `Out` and `N` are type
13036	parameters and `f` is instance data whose type selects code, which is the
13037	split [§8.2][s8-2] asks of an executor entry. `Out` is spelled rather than inferred
13038	from `f`, because the walk never infers through user code. `+`, `|` and `&`
13039	are variadic in Base, so `f(u...)` is the fold form at every arity, checked
13040	from one to four. Julia prints a parametric alias by its own name, so a build
13041	renders `Or{3}`. The nominal-type parameter is what [D-263][d-263] made every
13042	declaration: written at `Float64` and retyped by the walk. `out` keeps one
13043	name across the library and keeps wire paths ASCII.
13044	
13045	Annotation (2026-10-06): the printing sentence above holds only for an
13046	alias that is exported or defined in `Main`, where the probe ran. Inside
13047	`Redstone.Blocks` a build renders the full `Junction{Bool, Bool, 3,
13048	typeof(|)}`. The aliases are the spellings an author writes and reads in
13049	source. Whether they also print by name follows from the exported-name
13050	audit's ruling on the submodule, and is left to it.
13051	
13052	**Rejected.**
13053	- *Three separate types:* three copies of one shape, where the arity-via-type
13054	  derivation [§8.2][s8-2] blesses is validated once.
13055	- *Inferring `Out` from the fold's return type:* inference through user code,
13056	  which the walk forbids.
13057	- *A `Not` gate:* a one-input gate consolidates nothing, and the negation is
13058	  one character at the consumer.
13059	- *`Junction{In, N}` as a partial type defaulting `Out` to `In`:* a
13060	  convenience that scrambles the full type's reading order in every rendering
13061	  and message.
13062	- *`Σ` as the junction's output:* non-ASCII in a wire path, and the one output
13063	  name that would differ from the rest of the library.
