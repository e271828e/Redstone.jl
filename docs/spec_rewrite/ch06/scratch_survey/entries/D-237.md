8899	### D-237 — Classify a non-isbits immutable port type as one opaque leaf
8900	
8901	**Status.** ratified
8902	
8903	**Position.** The leaf walk over a port type descends through `Real`s, static
8904	arrays and isbits structs, and stops at an immutable type that is not isbits,
8905	treating it as one opaque leaf: a cell of that type holds the value itself,
8906	reference fields included. An opaque leaf is accepted by identity alone; the
8907	embedding lift ([D-238][d-238]) never enters it. A mutable type anywhere in a port value is
8908	refused (`IllegalPortType`), and so is a handle-typed face surfacing as a
8909	root input.
8910	
8911	**Spec.** [§4.3][s4-3], [§4.4][s4-4], [§8.2][s8-2], [§9.5][s9-5], [Appendix C][sC]
8912	
8913	**Rationale.** [§4.4][s4-4] already fixes the boundary: a bulk-data model is an
8914	immutable struct combining isbits parameters with references to data loaded at
8915	build time and frozen, never a `Ref`. The classification reads that
8916	description off the type, so an author declares nothing and the walk cannot
8917	drift from the prose. The store is the existing one: a handle type is its own
8918	leaf eltype with one homogeneous store, and Julia keeps an immutable struct
8919	with reference fields inline in an array, so the gather and the scatter are
8920	one load and one store, the allocation-free rebuild [§4.4][s4-4] promises. A handle
8921	may carry `T` among its isbits parameters; its cell is then a different type
8922	per activation, produced at `T` by the emitter's stage, and nothing embeds
8923	into it. An opaque leaf has no scalar positions to lift, so the relation
8924	accepts it by identity, and a handle built from literals at a `Dual`
8925	activation is refused at the probe with both types named; the remedy is to
8926	build it at `T`, or to pin the parameter in the declaration. The rule reads
8927	off the outermost type: a struct carrying a handle beside numeric fields is
8928	itself the opaque leaf, and [§4.4][s4-4]'s isbits parameters live inside the handle,
8929	never beside it. The wire relation ([D-236][d-236]) admits a handle at an abstract
8930	entry by the bound clause and needs no arm of its own.
8931	
8932	A root input of handle type has no synthesis (`probe_value`) and no producer.
8933	Refusing it keeps the field-emitting component, with its value-level
8934	constructor, as the one way bulk data enters a model; a caller-supplied root
8935	handle would be a second injection path, closed for the first cut ([D-008][d-008]).
8936	
8937	Annotation (2026-09-24): the type walk over a contract substitutes
8938	parameters and never fields, so a handle's references stay frozen with no
8939	stop of their own; a handle with a scalar parameter walks, and "pin the
8940	parameter in the declaration" is spelled `Pinned{Handle{Float64}}`. A
8941	mutable type's parameters pin by rule ([D-263][d-263]).
8942	
8943	Annotation (2026-09-25): the identity rule governs a store and the producer's
8944	own conformance check. At a wire the entry is a bound, and a frozen opaque
8945	arrival, from a `Pinned` producer or a discrete one, is admitted at an
8946	unpinned entry as the producer's cell ([D-264][d-264]).
8947	
8948	**Rejected.**
8949	- *An author-declared trait marking handle types:* a second place for the
8950	  boundary [§4.4][s4-4] already states, and one that can drift from it.
8951	- *Walking into the references (the built shape):* `leaf_types` descends into a
8952	  `Vector`'s fields, the build succeeds and the first gather dies in a raw
8953	  `MethodError`, neither supported nor refused.
8954	- *Supplying a handle-typed root input at build:* a second injection path
8955	  beside the value-level constructor, reopening what [D-008][d-008] closed.
