2509	### D-083 — Bind output-device reads to snapshot paths, not just faces
2510	
2511	**Status.** ratified
2512	
2513	**Position.** Output-device reads are snapshot-path bindings: writes speak the
2514	root contract (faces, claims, exclusivity — service by definition), reads see
2515	the whole table (inspection observation, the log/GUI/replay clients; local
2516	cells accessible — presentation filters are defaults, not walls).
2517	
2518	**Spec.** [§13.3][s13-3], [§13.5][s13-5], [§14.4][s14-4]
2519	
2520	**Rationale.** Attach validation against the `Build` makes structural drift
2521	loud; two-sided guidance — deep path = inspection (zero promises, right for
2522	this build), exported output face = integration (curated writer-independent
2523	meaning, the only shield against silent semantic drift under
2524	same-path/same-type substitution); generic consumers bind faces, aircraft
2525	families export conventional surfaces with wrapper types (`VelocityData` —
2526	field meaning defined at the type; wrong quantity = deliberate lie, not drift)
2527	as the checkable fraction of semantics; [§13.5][s13-5]'s observation-by-path rejection
2528	rests on the service/inspection split alone.
2529	
2530	**Rejected.**
2531	- *Faces-only reads:* export bloat: the root contract as a peripheral dumping
2532	  ground; no decoupling gained: diagnostic consumers are build-specific by
2533	  nature; unenforceable: the log and GUI already see everything; and
2534	  restricting reads does not create meaning-stability — exporting curated
2535	  surfaces does.
2536	- *Semantic validation machinery:* meaning is not in the schema; the
2537	  wrapper-type idiom is the checkable fraction.
