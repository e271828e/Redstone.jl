is admitted the same way. The identity rule for an opaque leaf governs a store, never a wire 
(§9.5, D-264). Under that rule, a component that re-emits a frozen handle pins that output too, so a 
handle's pin is a property of its chain (D-264).
A violation of the walk clause is WalkingFaceAtFrozenEntry, naming both endpoints, the leaf and both 
declared leaf types. The message carries both remedies, "remove the entry's Pinned if the consumer 
promotes; feed it from a non-walking source if the freeze is genuine". The Freeze block is the one-
line spelling of the second remedy (§13.7, D-266).
The walk clause also gives the two sides of a contract (a component's declared interface) their failure 
asymmetry. A pin written at an entry whose consumer really promotes fails at the first nominal 
build, at the wire, with both endpoints named ( D-263). It fails there because an input has a build-
time counterparty. The output side has none, so a pin written at a leaf that really participates lurks 
until the first Dual activation. It lurks loudly, never silently (§8.2, D-286).
Connections per port
Fan-out is free. One producer may feed many consumers. The converse is strict. Every input port 
takes exactly one connection , with no exceptions ( D-170). Aggregation is done by junctions 
(§6.2).
The rule spans levels ( D-170). A child input fed by a local wire at its own level and handed up 
through its parent's input_wires is a two-producers build error, TwoProducers. Routing a face upward 
cannot silently double-feed.
There is no auto-bubbling of unconnected inputs (D-043). Unconnected input ports are a build error, 
with no silent defaults. The check is a whole-tree property, not a per-declaration one (D-048). Both 
this check and the two-producers check are decided at the root, since neither is decidable below it 
(D-048). Within a single assembly declaration an unfed child input is simply awaiting a wire from 
above, either a local wire or an input_wires entry handing the obligation up one level ( §8.6). The 
unconnected-input error, UnconnectedInput, fires at the root build for any input whose obligation 
chain never terminates. The one legitimate terminus fed by no component is the root component's 
own input face, a root input (§11.3, D-208).
Unconnected output ports are legal, silently, with no build­time warning (D-084).
6.2 Aggregation: explicit summing junctions
Several physical quantities are totals over many contributors. Total wrench (force and torque), total 
mass properties and total internal angular momentum are the examples. In Flight.jl these totals 
come from tree walks. FlightPhysics' generated functions get_wr_b, get_mp_b and get_hr_b sum each 
quantity over a model tree. This section states the rule and the junction that carries it. It then covers 
what the explicit form buys, the hierarchical aggregation idiom, zero contributors and the cost.
N­to­1 physical aggregation is expressed by ordinary junction components and explicit 
wires (D-037).
There is no framework aggregation mechanism. There are no multi-connection ports, no declared 
fold ops and no identity-element opt-outs. Every input port takes exactly one connection, every -
where (§6.1).
