745	### D-020 — Boundary event phase iterates to quiescence
746	
747	**Status.** ratified
748	
749	**Position.** Boundary event phase iterates to quiescence — rounds of full
750	re-sweep → guards → handlers (declaration order, per-event re-decode) — each
751	event firing at most once per boundary, with "newly fired" made precise via
752	per-event baselines in loop state ([D-082][d-082]); due `g` updates run after
753	quiescence, outside the iteration.
754	
755	**Spec.** [§2.2][s2-2], [§3.1][s3-1], [§10.6][s10-6]
756	
757	**Rationale.** Recorded only through the rejections below.
758	
759	Annotation (2026-10-02): amended by [D-154][d-154] and [D-181][d-181]. The per-event
760	re-decode is removed, and once-per-boundary firing gives way to the per-event
761	`firing_budget`. The iteration to quiescence and the ticks after it stand.
762	
763	**Rejected.**
764	- *Single pass per boundary:* cascade latency N·h — step-size-dependent
765	  semantics, the [§2.2][s2-2] `f_step!` footgun class, made common by [§3.1][s3-1] externalized
766	  FSMs.
767	- *Bounded-rounds cap:* arbitrary K knob; livelock burns the budget then errors
768	  instead of degrading to Tier-1 granularity.
769	- *Event/tick fixed-point iteration:* structurally unnecessary — `z⁺` is
770	  invisible until the next tick decode.
