613	### D-016 — Uniform component interfaces via `h_x` and per-event re-decode
614	
615	**Status.** ratified
616	
617	**Position.** Uniform component interfaces via the no-feedthrough state decoder
618	`h_x`, with selective auto-publication of declared state/mode fields ([D-035][d-035]);
619	guards and handlers read the fresh boundary table, with per-event re-decode
620	(`handler → project → h_x → h_xu`); `project` is the sole raw-state function
621	(schedule-structural).
622	
623	**Spec.** [§4.2][s4-2], [§5.3][s5-3], [§7.4][s7-4], [§10.6][s10-6], [§8.3][s8-3], [Appendix D][sD]
624	
625	**Rationale.** Recorded only through the rejections below.
626	
627	Annotation (2026-10-02): superseded in part. [D-154][d-154] removes the per-event
628	re-decode and [D-252][d-252] the selective auto-publication. `h_x` as the uniform
629	state decoder and `project` as the sole raw-state function stand.
630	
631	**Rejected.**
632	- *Superseded position — identity publication of state and modes as the
633	  default, plus an unlisted-port convention for interface noise (the earlier
634	  design of record):* retired because contract visibility ([D-034][d-034]) makes
635	  publicity a declaration, and `unlisted` pretended privacy without enforcing
636	  it (hidden but connectable).
637	- *Passing state alongside `y`:* double-passing; two idioms in the wild.
638	- *Fully private discrete state:* breaks uniformity; the codebase culturally
639	  publishes state anyway.
640	- *One-handler-per-component-per-boundary restriction:* the cheap per-event
641	  re-decode removes the need.
642	- *Exposing `z` without an unlisted convention:* RNG/log noise.
643	- *The `unlisted` motivating case — RNG state feeding the component's own
644	  update:* dissolved entirely once [D-035][d-035] gave every function direct `x` views,
645	  so nothing needed publishing to be readable.
