10590	### D-265 — Read the `Pinned` marker at the top of an entry alone
10591	
10592	**Status.** ratified
10593	
10594	**Position.** `Pinned{P}` is read at the top of a contract entry and nowhere
10595	else. A marker below the top, in a type parameter (`SVector{2,
10596	Pinned{Float64}}`, `Mixed{Float64, Pinned{Float64}}`), is `IllegalPortType`
10597	on both tiers. A field that must not follow the scalar is typed concretely in
10598	its struct (`b::Float64` beside `a::T`), which freezes it for every user of
10599	the type; a whole leaf is pinned with the marker.
10600	
10601	**Spec.** [§8.2][s8-2], [Appendix C][sC]
10602	
10603	**Rationale.** `retype`'s recursion into type parameters fired the marker's
10604	arm at any depth, so a nested marker was stripped and acted as the
10605	parameter-position pin [D-263][d-263] rejected: `Mixed{Float64, Pinned{Float64}}`
10606	retyped to `Mixed{T, Float64}`. [D-263][d-263]'s ground stands. The spelling is
10607	half-working, because the marker is not `<: Real`, so `Bounded{T<:Real}`
10608	raises a `TypeError` on the same marker `SVector` accepts, and a form that
10609	works on some types and not others is worse than none. It also gave two
10610	spellings for one meaning, `SVector{2, Pinned{Float64}}` beside
10611	`Pinned{SVector{2, Float64}}`. On the discrete tier the declaration is read
10612	as written and the wrong-tier check looks at the top constructor only, so a
10613	nested marker slipped past it, reached the wire pass as a literal type and
10614	failed as a `WireTypeMismatch` that misnamed the fault; unwired, the literal
10615	`Pinned{Float64}` is an empty isbits struct with zero leaves.
10616	
10617	The recorded limit is per-type against per-declaration freezing. The
10618	parameter-position pin would have made the freeze a per-declaration choice,
10619	the same struct with `b` walking in one component's contract and pinned in
10620	another's. The concrete field makes it a per-type choice. That is the right
10621	home for the fact: a field that must not walk is almost always frozen by
10622	nature, a count, a mode flag, a calibration constant, a reference to
10623	build-time data, and the struct definition is where a reader expects to
10624	learn it. The struct's own constructor enforces the freeze on the producer
10625	side, since a stage that hands a `Dual` for a `Float64` field dies in
10626	`convert`, and the wire relation admits `MixedRight{Float64}` at
10627	`MixedRight{Dual}` by embedding at the parameter. One consequence for the
10628	reader's rule: "every `Float64` position follows the scalar" reads the
10629	declaration as written, so a concretely typed field is frozen without
10630	appearing in the contract, the mild reader-opacity [D-263][d-263] accepted for one
10631	walk rule instead of two. `IllegalPortType` is the kind because the offending
10632	type is outside the leaf vocabulary as written, which is what its other arms
10633	name.
10634	
10635	**Rejected.**
10636	- *Admitting the nested spelling as a second legal form:* reopens [D-263][d-263]'s
10637	  rejected item, with the `<: Real` failure and the duplicate spelling it
10638	  recorded.
10639	- *A kind of its own for the nested marker:* `IllegalPortType` already names
10640	  a declared type the vocabulary does not admit, with the declaration and the
10641	  port in its payload.
10642	- *Refusing the nested marker while leaving `retype`'s arm in place:* the
10643	  refusal would guard a walk that still strips at any depth, a latent trap;
10644	  the top-only read removes the arm.
10645
