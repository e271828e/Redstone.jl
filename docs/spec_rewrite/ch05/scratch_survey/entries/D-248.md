9386	### D-248 — Frame every user-authored method the build invokes, declarations included
9387	
9388	**Status.** ratified
9389	
9390	**Position.** The build frames every user-authored method it invokes through
9391	one framing accessor, and a throw out of one is `UserCodeFraming`, fail-fast,
9392	carrying the component path, the function, the bundle's field names, the
9393	synthesized inputs as a spelling and the original exception as `cause`.
9394	
9395	- The framed set is the declarations of [§8.2][s8-2] and the probed functions of [§9.3][s9-3]
9396	  alike. [D-142][d-142]'s list is its inputs-bearing subset.
9397	- The probe context is carried as names and a spelling, never as values,
9398	  under [§13.2][s13-2]'s strings-never-instances rule.
9399	- A `DiagnosticError` carrier, an `InternalInvariant` and an
9400	  `InterruptException` pass through the frame unwrapped.
9401	- A `FieldError` matched against the bundle is `BundleFieldError` at the
9402	  probe and a `StepError` species at [§13.4][s13-4]'s catch site. The probe
9403	  matches by the bundle's own type, which its accessor holds; the catch site
9404	  matches by the bundle's field names, since the activation's bundle type is
9405	  not in hand there. `UserCodeFraming` stays build-only.
9406	
9407	**Spec.** [§5.2][s5-2], [§9.3][s9-3], [§13.2][s13-2], [§13.4][s13-4], [Appendix C][sC]
9408	
9409	**Rationale.** [D-142][d-142]'s totality contract lists the functions that receive a
9410	bundle, because totality is a claim about inputs. A declaration takes none,
9411	so the bundle-law diagnostic cannot arise inside it, but any other throw can.
9412	Today such a throw escapes `build` raw from whichever of the fourteen call
9413	sites reads the declaration first, with no component path and in no
9414	framework vocabulary, while every other user-code failure at build will name
9415	its path and function once the frame lands. Framing costs nothing at
9416	runtime. The frame is build-time work, a try block on the non-throwing path
9417	is a handler push and pop, and the runtime side adds a classification at the
9418	catch site that already exists rather than a new try. One accessor over the
9419	fourteen sites keeps the frame from being fourteen try blocks, and removes
9420	the repeated re-reads of `init_m` on the way. The context payload reads
9421	"including synthesized inputs" as a spelling because the values would be
9422	instances of the author's own port types, which [§13.2][s13-2] keeps out of every
9423	payload and [D-216][d-216] licenses as spellings.
9424	
9425	**Rejected.**
9426	- *Framing [D-142][d-142]'s list alone:* leaves the declarations the one user-code
9427	  surface that fails outside the framework's vocabulary, for no runtime
9428	  saving.
9429	- *One frame per stratum, recovering the function from the backtrace:* the
9430	  frame would name the function by scraping a stack, which [§13.2][s13-2]'s
9431	  structured-not-textual rule forbids.
9432	- *The bundle's values in the payload:* instances of the author's port types
9433	  in a diagnostic, against the strings-never-instances rule.
9434	- *A `UserCodeFraming` species at runtime:* the runtime carrier already
9435	  names the frame and the function through the cursor and carries the
9436	  cause. A second wrapper would say the same thing twice.
