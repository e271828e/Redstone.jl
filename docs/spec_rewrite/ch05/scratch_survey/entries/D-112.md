3404	### D-112 — Add `events` to the tier-consistency markers
3405	
3406	**Status.** ratified
3407	
3408	**Position.** `events` joins the tier markers: the tier-consistency rule
3409	enumerates four declaration families — stage names, the `init_*` family,
3410	`workspace` arity, and (when declared) `events`, a continuous-tier marker since
3411	the event system is continuous-side only.
3412	
3413	**Spec.** [§3.2][s3-2], [§5.2][s5-2], [§8.2][s8-2], [Appendix C][sC]
3414	
3415	**Rationale.** The kind is widened and renamed `StageOnWrongTier` →
3416	`DeclarationOnWrongTier` (payload: the offending declaration — a stage name or
3417	`events` — and the tier the leaf's other declarations announce): one rule, one
3418	kind, keeping the kind list flat (user's call — the exception list is long
3419	already); [D-075][d-075] amended.
3420	
3421	**Rejected.**
3422	- *A separate `EventOnWrongTier` beside `StageOnWrongTier`:* additive and
3423	  rename-free, but mints a second kind for the same tier-agreement rule —
3424	  taxonomy economy won.
3425	- *Leaving `events` outside the rule:* a discrete leaf declaring `events` is
3426	  illegal by [§5.2][s5-2]/[§3.2][s3-2]/[Appendix B][sB]'s testimony yet checkable nowhere, and
3427	  tier-exclusive `events` outside a list that includes tier-symmetric
3428	  `workspace` is indefensible asymmetry.
