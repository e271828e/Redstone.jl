5340	### D-152 — Join auto-publication to the per-event re-decode at stage 1
5341	
5342	**Status.** superseded → [D-154][d-154]
5343	
5344	**Position.** **Auto-publication joins the per-event re-decode at its stage-1
5345	position** — the sequence is `handler → project → auto-publish → h_x → h_xu`,
5346	the framework rewriting the firing component's auto-published cells from the
5347	just-latched state stores, so a later handler of the same component reads `y`
5348	coherent with the live `x`/`m`.
5349	
5350	**Spec.** [§5.3][s5-3], [§10.6][s10-6]
5351	
5352	**Rationale.** A round-5 kernel dry-run finding (finding 5), amending [D-016][d-016].
5353	Auto-published cells belong to no stage ([§9.5][s9-5]), so [D-016][d-016]'s stages-only
5354	spelling left them stale between same-component events (a second handler
5355	reading its own auto-published mode/state port — the Engine's `ω`, the LQR's
5356	`sat_out_0` — would latch a pre-transition value silently, the next round's
5357	re-sweep repairing the cell but not the latched value).
5358	
5359	**Rejected.**
5360	- *Stage-products-only handler-phase `y` with the hole documented:* preserves
5361	  [D-016][d-016]'s letter but silently abandons the `y = h(x)` coherence invariant that
5362	  motivates live `y` in the first place, precisely for the mode- and
5363	  state-publishing components most likely to carry multiple events.
