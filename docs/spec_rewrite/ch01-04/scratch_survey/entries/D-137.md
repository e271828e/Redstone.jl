4425	### D-137 — Bound snapshot-log retention by count, with amortized doubling stride
4426	
4427	**Status.** ratified
4428	
4429	**Position.** Snapshot-log retention gets a **bound**, `log_max` — the maximum
4430	number of retained snapshot references, a new `Simulation` keyword beside
4431	`log`/`log_every`.
4432	
4433	**Spec.** [§4.1][s4-1], [§4.4][s4-4], [§7.5][s7-5], [§10.7][s10-7], [§11.2][s11-2], [§11.5][s11-5], [§11.8][s11-8], [§12.4][s12-4], [§12.7][s12-7], [§13.5][s13-5],
4434	Appendices B/D
4435	
4436	**Rationale.** **A count, not a memory budget**: snapshots are immutable object
4437	graphs with internal sharing ([§4.1][s4-1], and [§4.4][s4-4] field handles riding as references
4438	to build-time-frozen data, [§7.5][s7-5]), so byte accounting over them is fuzzy and
4439	platform-dependent, while a count is exact and converts to memory through one
4440	number the user measures once (`Base.summarysize` of a single snapshot).
4441	**Default 65536 (2¹⁶), finite unconditionally**, with `Inf` the explicit
4442	opt-out — no modal rule keyed on `t_end`; a finite run shorter than the bound
4443	never notices it, and at 50 Hz full density 2¹⁶ boundaries is ≈22 minutes
4444	before the first drop. **When the log fills, the effective retention stride
4445	doubles** — `log_every · 2^k` after k generations — so the bound holds while
4446	coverage stays **global**: the whole run remains plottable at coarsening
4447	density, which is [D-038][d-038]'s division of labor carried through (the log's chief
4448	consumer is the post-run plot of a session as a whole; full density over any
4449	*segment* of interest is what replay from the trace recovers, [§11.5][s11-5], [§12.7][s12-7]). The
4450	licence is [D-038][d-038]'s own asymmetry, a fortiori: a thinned log costs resolution in
4451	a *view*, never a record, whereas [D-029][d-029]'s refusal to thin the trace stands
4452	untouched. Following [D-135][d-135]'s precedent, **the guarantees are normative and the
4453	mechanism a sketch**: normatively the retained count never exceeds `log_max`,
4454	coverage is global at the effective stride, and the endpoints are kept; the
4455	sketch is that the thinning is **amortized** — the stride doubles immediately
4456	and each subsequent retained append also releases one predecessor of the
4457	previous generation (a cursor over the odd indices, O(1) amortized, physical
4458	compaction once per generation), the generation's thinning completing exactly
4459	when its refill does. Amortization is a responsiveness choice: a one-shot
4460	halving would make ~`log_max/2` *old-generation* snapshots unreachable at a
4461	stroke, a major-GC burst worth a pacer-absorbed, `DebtReanchor`-visible hiccup
4462	([§10.7][s10-7]) — exponentially rare, the wall-clock gap between generations doubling,
4463	but needless — while the amortized form drops exactly one old snapshot per
4464	retained append, the steady trickle a rolling window would produce anyway; the
4465	loop's own work is pointer bookkeeping, microseconds either way and on the
4466	framework side of [§7.5][s7-5]'s scope, publication staying wait-free with readers
4467	never blocking. **The boundary-zero ([§14.5][s14-5]) and terminal ([§12.4][s12-4](1), [§13.5][s13-5])
4468	snapshots are retained unconditionally under any `log_every` and any `log_max`,
4469	and do not count against the bound** — two extra references — so the run's
4470	endpoints and, via the terminal status's final cumulative counters ([§11.8][s11-8],
4471	[D-136][d-136]), its complete diagnostic account always survive. Compositions stated
4472	once: `totals` monotonicity across logged snapshots ([§11.8][s11-8]) is unaffected,
4473	re-decimation losing *which* boundary in a stretch an occurrence fell on and
4474	never *how many*; and `log_max` is a **view policy, not
4475	trajectory-determining** — outside the trace header's deployment block, neither
4476	recorded nor compared by replay ([D-127][d-127], [D-133][d-133]'s compared set untouched). [§7.5][s7-5]'s
4477	`sizehint!` for the expected duration is reconciled: now capped by `log_max`,
4478	which is also what defines the hint when `t_end = Inf`. No new diagnostic kind
4479	— hitting the bound is stated policy, not an event to report.
4480	
4481	**Rejected.**
4482	- *A rolling window:* optimizes recent-past-at-full-density, which replay
4483	  already serves, at the cost of the whole-run overview replay is expensive for
4484	  — and it buys no responsiveness either, its steady-state drop rate being
4485	  exactly the amortized form's.
4486	- *A memory-based bound in bytes:* false precision over shared immutable graphs
4487	  — the number would be platform-dependent and unauditable, where a count is
4488	  exact and one measurement converts it.
4489	- *A modal default, finite only when `t_end = Inf`:* a modal rule where one
4490	  unconditional number suffices, and the finite-`t_end` run it exempts is the
4491	  one that never reaches the bound anyway.
4492	- *An unbounded default, the status quo under review:* gigabytes per hour at
4493	  C172X scale and 50 Hz in the configuration [Appendix B][sB] calls the honest
4494	  interactive default, ending in an OOM no diagnostic mentions.
4495	- *One-shot halving as the normative mechanism:* an old-generation major-GC
4496	  burst once per generation — pacer-absorbed and rare, but needless when
4497	  amortization achieves the rolling window's trickle profile at the same
4498	  asymptotic cost.
4499	- *A diagnostic kind for reaching the bound:* a policy operating exactly as
4500	  configured is not a warning, and the log's density is visible in the log
4501	  itself.
