13395	### D-316 — Stop requests are structural: a `StopFlag` port ends the run unless the advance ignores it
13396	
13397	**Status.** ratified
13398	
13399	**Position.** A model requests a stop by publishing a port of the framework
13400	enum `StopFlag`, and every request ends the run at the first publication
13401	where it holds, unless the advance ignores it.
13402	
13403	- `StopFlag` is `@enum StopFlag NO_STOP STOP_REQUESTED`, defined beside
13404	  `Pinned`. An enum is one leaf of its own eltype, pinned at every
13405	  activation, so every `StopFlag` port lands in one per-eltype cell block
13406	  ([§4.3][s4-3], [§9.7][s9-7]). An output port whose type is exactly `StopFlag` is a stop
13407	  request, whoever publishes it.
13408	- Two placements are `IllegalPortType`. `:stop_flag_nested` is a `StopFlag`
13409	  leaf inside a port whose type is not `StopFlag` itself, a struct field or
13410	  a static array of them, since the roster is per port. `:stop_flag_at_root`
13411	  is a root input whose type carries a `StopFlag` anywhere, bare or nested,
13412	  since a request is the model's, never an operator's ([§12.1][s12-1]). A
13413	  `StopFlag` input port places nothing and is left alone.
13414	- `stop_reason(c)` is an optional declaration with default `""`, which the
13415	  build consults for every component that publishes a `StopFlag` port. One
13416	  reason serves all of a component's `StopFlag` ports. The `String` is
13417	  instance data on the component, never a port value. `stop_reason` is a
13418	  family name: [§8.1][s8-1]'s import list carries it and [D-246][d-246]'s shadowing check
13419	  covers it.
13420	- The activation's cell layout carries the requester roster,
13421	  `requesters::Vector{Requester}`, one `Requester(path, port, reason)` per
13422	  `StopFlag` output port. It is index-aligned with the `StopFlag` cell block,
13423	  entry `i` owning offset `i - 1`, and it is written by address after
13424	  placement, never by walk order. Roster order is build order.
13425	- `StopRequest(; reason = "")` in `Redstone.Blocks` is the library spelling,
13426	  a stateless continuous leaf in the mould of `Constant`: a `Bool` input
13427	  `request`, a `StopFlag` output `flag`, and its reason as its
13428	  `stop_reason`. Continuous, it refreshes at every boundary, `t*` included,
13429	  and one leaf sits anywhere in the tree ([§10.5][s10-5], [D-019][d-019]). Fed by a discrete
13430	  detector, it sees the tick at the tick's own boundary ([§10.5][s10-5], [D-147][d-147]).
13431	- `StopPolicy` is `t_end` plus `ignored`, the requester paths the advance
13432	  does not honour. `run!`, `replay!` and `step!` take
13433	  `ignore_stop_requests = ()` in place of `stop_on`. `()` ignores none,
13434	  `:all` every roster path, and an iterable of strings names requesters by
13435	  component path, validated path by path against the roster, duplicates
13436	  collapsed, in the order given. A path naming no requester is
13437	  `StopRequestInvalid(path, site, candidates)`, collected over the given
13438	  paths, `candidates` the roster's paths in roster order.
13439	- The binder returns the policy and an ignore mask, one `Bool` per
13440	  requester, `true` where ignored. The mask replaces the faces' compiled
13441	  addresses as the loop's argument. The policy is the advance's value and
13442	  the mask its compiled companion ([D-261][d-261]).
13443	- After every publication the loop scans the `StopFlag` cell block of the
13444	  just-published snapshot. It stops on the first entry in roster order that
13445	  is honoured and reads `STOP_REQUESTED`, with
13446	  `ModelRequestedStop(path, port, reason)` as the source. [D-203][d-203]'s source
13447	  order is unchanged, the requests read where the faces were: a control stop
13448	  at frame top, then `t_end`, then the requests at each publication.
13449	- `UnboundedRun` fires at `run!` in `:live` when `t_end` is `Inf` and no
13450	  requester is honoured, the model having none or the advance ignoring them
13451	  all. Its payload is `t_end` and `ignored`, and its message says which case
13452	  holds.
13453	- The `stop_on` keyword and `StopFaceInvalid` retire. A root-exported `Bool`
13454	  face stays legal and inspectable, and it stops nothing.
13455	
13456	Supersedes [D-060][d-060]'s publication and policy clauses, the root-exported `Bool`
13457	face and `stop_on`, and its rejection of scanned terminal types, and narrows
13458	its observation-by-path rejection; [D-255][d-255]'s `stop_on` keyword with its
13459	no-faces default; and [D-261][d-261]'s bullet making `StopPolicy` `t_end` and the stop
13460	faces with the faces' compiled addresses as the loop's argument. [D-060][d-060]'s rule
13461	that termination is state, never an exception, stands.
13462	
13463	**Spec.** [§4.3][s4-3], [§8.1][s8-1], [§8.2][s8-2], [§10.4][s10-4], [§12.4][s12-4], [§12.6][s12-6], [§12.7][s12-7], [§13.5][s13-5], [§13.7][s13-7], [§14.4][s14-4], [Appendix B][sB], [Appendix C][sC]
13464	
13465	**Rationale.** A model-detected stop was a `Bool` face re-exported level by
13466	level to the root and named by the advance's `stop_on`, and the hop per
13467	level was the pain: one `output_wires` entry at every assembly between the
13468	detector and the root, for every stop. A component author who wires a stop
13469	is saying that the component's validity assumptions broke down and that
13470	continuing is at the integrator's own risk. Stopping is therefore the rule
13471	and continuing the exception. The request becomes structural by default and
13472	overridable per advance, and the per-level plumbing goes.
13473	
13474	The vocabulary is an eltype rather than a block because cells are stored per
13475	eltype ([§9.7][s9-7], [D-162][d-162]). Every `StopFlag` port lands in one buffer, and the
13476	loop's check is a scan of that buffer on the snapshot it just published,
13477	allocating nothing; the roster is touched on a hit only. [§13.7][s13-7]'s doctrine
13478	that library blocks have no framework privileges stands. The privilege is
13479	the eltype's, as `Pinned` is a framework marker, and `StopRequest` is a
13480	spelling of a port any component may declare. The nested refusal keeps the
13481	roster per port. The root-input refusal keeps a request the model's, the
13482	control plane being the operator's path.
13483	
13484	The reason is a declaration because it is text, and the build reads it once.
13485	`stop_reason` joins the declaration family because an optional declaration
13486	has no absence to notice: a foreign `stop_reason` would silently read `""`,
13487	which is the case [D-246][d-246]'s check exists for. `condition` stays outside the
13488	family because a foreign `condition` fails loudly, as a `MethodError` at the
13489	owner's pull.
13490	
13491	[§13.5][s13-5]'s observation-by-path rejection stands narrowed. The ignore list reads
13492	no arbitrary cell. It addresses the `Build`'s requester roster, a build
13493	product like the root-input list, and it binds at an advance, a stopped-sim
13494	point where conditions already address state by path ([§14.1][s14-1]). [D-060][d-060]'s
13495	scanned-terminal-type rejection is superseded on its own terms. The
13496	requester is loud at inspection, since the roster and the termination record
13497	name it. Substitution is answered by the override, and disabling is one
13498	keyword. The trigger is the author's knowledge and the override the
13499	integrator's, which is where each belongs. An ignored request is still a
13500	cell in every snapshot, so the log records when validity broke even on a run
13501	that continued. Two uses share the mechanism, validity breakdown and
13502	scenario completion, and the reason string is what tells a reader which; the
13503	framework never will.
13504	
13505	**Rejected.**
13506	- *Superseded position — a `Bool` face re-exported to the root and named by
13507	  `stop_on` ([D-060][d-060], [D-255][d-255]):* one wiring entry per level for every stop, and
13508	  an advance naming no face integrated a terminal state to `t_end` with
13509	  nothing complaining. Flagging faces as stop candidates and diagnosing the
13510	  dropped re-export, the remedy `pending.md` held, treated the symptom and
13511	  kept the plumbing.
13512	- *Honouring requests by an opt-in token, default off:* halves the gain,
13513	  since the integrator must still name every stop, and inverts the author's
13514	  meaning, which is that continuing is the exception.
13515	- *A global-only override:* the per-requester mask costs a name lookup the
13516	  binder already does, and a scenario that wants one stop and not another
13517	  would have no spelling.
13518	- *A `terminal` event flag, and stop faces addressed by deep path:* [D-060][d-060]'s
13519	  grounds stand for those. The localization a terminal flag promises is the
13520	  event idiom feeding a request anyway, and a path-addressed face makes any
13521	  output a trigger, which is observation-by-path in full.
13522	- *Reading the reason off the block by type:* the build cannot know
13523	  `Blocks`, which is included last, and a reason confined to one block type
13524	  would leave every direct publisher without one.
