4722	### D-141 — Continuous state resets are events, owned by the reimplemented PIVector
4723	
4724	**Status.** ratified
4725	
4726	**Position.** A continuous component's state reset is an event — a new Appendix
4727	A entry, with the tier asymmetry now taught as a contract: the same-tick reset
4728	entry is marked explicitly discrete-tier, and [§5.3][s5-3]'s gear sentence is extended
4729	to say why. [§3.1][s3-1], [§2.1][s2-1] and [§13.7][s13-7] are unchanged. Even a commanded continuous
4730	reset — the condition arriving as an ordinary `Bool` input, weight-on-wheels
4731	being the shipped instance — is spelled as an event whose guard reads that
4732	input; the discrete tier's input answer does not transfer. Ownership settles on
4733	the reimplemented `PIVector`, which gains a flag-gated reset face: `PIVector(;
4734	reset = true)` adds a `Bool` input face plus the event, the default omits both,
4735	under one fixed policy — rising edge → reset to the declared `init_x` values,
4736	implemented internally as an ordinary guard/handler event (the [Appendix A][sA]
4737	contract's worked instance). The gear wires `strut.wow → frc.reset` (the
4738	touchdown edge).
4739	
4740	**Spec.** [§2.1][s2-1], [§3.1][s3-1], [§3.3][s3-3], [§10.6][s10-6], [§8.5][s8-5], [§13.7][s13-7], [§5.3][s5-3], [Appendix A][sA]
4741	
4742	**Rationale.** The reason is semantic, not stylistic: only the discrete tier's
4743	update stage is already a jump map (a reset there is merely another value for
4744	`z⁺`), whereas a continuous state jump must be solver-visible and land between
4745	integration segments — the invariant every hybrid tool enforces (Simulink
4746	zero-crossing plus solver restart, Modelica `reinit` legal only inside `when`,
4747	SUNDIALS stop-and-`ReInit`, DiffEq.jl callbacks), which is also why [§3.1][s3-1]'s
4748	immutable stage views are enforcement of mathematics rather than a
4749	discretionary restriction. No stale-output hazard rides along: [§10.6][s10-6] re-sweeps
4750	outputs to quiescence after handlers, so a continuous edge-reset is
4751	same-boundary by construction. The structural argument is that events are
4752	leaf-owned — a handler resets its own `x`, and assemblies have no events — so
4753	the state's owner is the reset's only possible home, and a cross-component
4754	reset becomes a wired guard input to it. The demand test: genre precedent
4755	counts as demand for a domain block's feature set (external-reset ports on
4756	integrator and PID blocks are standard vocabulary — Simulink, PLC PIDs) even at
4757	a single migration consumer, which is how [§13.7][s13-7]'s grow-by-migration-demand rule
4758	reads past a literal one-consumer count. `strut.wow → frc.reset` gives fresh
4759	regulator state per contact episode, boundary-detected (the regulator's input
4760	ramps from zero at touchdown) and harmless at boundary zero for a sim
4761	initialized on ground. `PistonEngine`'s two `PIVector` instances (`idle`,
4762	`frc`) are verified reset-free in today's code (`piston.jl:295-449`: `f_ode!`
4763	runs both in every engine state, `f_step!` does mode transitions only,
4764	`f_init!` sets gains; windup across unused phases is already handled by the
4765	saturation bounds and `int_halted`) and migrate untouched with the flag off,
4766	their `f_init!` gain writes becoming construction-time parameters ([D-089][d-089]). The
4767	PI law is shared as plain pure functions called by the block's stages ([D-139][d-139]'s
4768	laws-as-plain-functions pattern), and `sat_ext` poses the same
4769	always-on-vs-flag-gated face question, decided at reimplementation time on the
4770	same axis. Recorded as general doctrine, the graduation rule: a wrapper's
4771	pattern moves into the library at the second same-semantics demand.
4772	
4773	**Rejected.**
4774	- *Superseded position — a gear-owned `FrictionRegulator` leaf wrapping the PI
4775	  law:* it buys a duplicated component whose only job is to keep the library
4776	  block reset-free; leaf ownership already cuts toward the block, since the
4777	  wrapper would have to own the state to own the event, and genre precedent
4778	  supplies the demand a one-consumer count seemed to withhold.
4779	- *An always-on reset face:* taxes every non-user — the engine's two instances
4780	  first — with wire-false ceremony, or leaves an unwired `Bool` face that
4781	  becomes a root slot the frozen roster, the trace header and every condition
4782	  baseline must then speak about.
4783	- *Simulink's full policy menu (rising/falling/either/level triggers plus an
4784	  external-IC port):* one policy suffices, with [§13.7][s13-7]'s Bool gates covering
4785	  falling-edge consumers and separate blocks covering level-pinning and
4786	  reset-to-an-external-value, which is tracking — each extra option is contract
4787	  surface every reader of the block carries forever.
4788	- *The liftoff edge (`!wow`):* behaviorally closest to today's level reset, but
4789	  equivalent only because `Strut`'s no-contact branch returns `v_ec_xy = [0,0]`
4790	  and the integrator leaks — component A's reset correctness resting on
4791	  component B's default branch, precisely the cross-component dependency the
4792	  touchdown edge dissolves rather than documents.
4793	- *Relaxing [§3.1][s3-1]'s immutable views* so stage methods could write `x`: forbidden
4794	  by ODE-solver mathematics, not by taste — trial-point stage evaluations,
4795	  error control and dense-output interpolants all presume in-segment
4796	  continuity, and mid-segment mutation corrupts all three.
4797	- *An assembly wrapping a `PIVector` child and resetting it externally:*
4798	  structurally impossible — events are leaf-owned and an assembly has no
4799	  dynamics of its own, [§3.3][s3-3].
4800	
4801	**Divergence.** Simulink exposes this as a checkbox; the framework's flag-gated
4802	reset face is "the honest version" — declarations are ordinary functions of the
4803	instance ([§8.5][s8-5]), not an opaque toggle.
