3440	### D-112 — Add `events` to the tier-consistency markers
3441	
3442	**Status.** ratified
3443	
3444	**Position.** `events` joins the tier markers: the tier-consistency rule
3445	enumerates four declaration families — stage names, the `init_*` family,
3446	`workspace` arity, and (when declared) `events`, a continuous-tier marker since
3447	the event system is continuous-side only.
3448	
3449	**Spec.** [§3.2][s3-2], [§5.2][s5-2], [§5.3][s5-3], [§8.2][s8-2], [Appendix C][sC]
3450	
3451	**Rationale.** The kind is widened and renamed `StageOnWrongTier` →
3452	`DeclarationOnWrongTier` (payload: the offending declaration — a stage name or
3453	`events` — and the tier the leaf's other declarations announce): one rule, one
3454	kind, keeping the kind list flat (user's call — the exception list is long
3455	already); [D-075][d-075] amended.
3456	
3457	**Rejected.**
3458	- *A separate `EventOnWrongTier` beside `StageOnWrongTier`:* additive and
3459	  rename-free, but mints a second kind for the same tier-agreement rule —
3460	  taxonomy economy won.
3461	- *Leaving `events` outside the rule:* a discrete leaf declaring `events` is
3462	  illegal by [§5.2][s5-2]/[§3.2][s3-2]/[Appendix B][sB]'s testimony yet checkable nowhere, and
3463	  tier-exclusive `events` outside a list that includes tier-symmetric
3464	  `workspace` is indefensible asymmetry.
