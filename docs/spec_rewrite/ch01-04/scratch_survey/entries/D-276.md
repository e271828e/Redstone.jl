11554	### D-276 — Address a leaf inside a port value by a dotted leaf address
11555	
11556	**Status.** ratified
11557	
11558	**Position.** The second argument of every read selector is a *leaf address*,
11559	a string naming one leaf of the addressed field: the field or face name,
11560	followed by `.name` and `[k]` or `[k,l]` steps in any order.
11561	`get_output("kin", "pose.q_eb[2]")`, `get_state("dyn", "ω_eb_b[1]")` and
11562	`get_input("wind[1]")` are the spellings. The trailing component index of
11563	[D-271][d-271] retires.
11564	
11565	- A bare `Symbol` is the short form of a plain field or face name:
11566	  `get_state("kin", :θ)` is `get_state("kin", "θ")`.
11567	
11568	  Annotation (2026-09-30): a face name may contain a dot ([§8.6][s8-6], the house
11569	  style of [§8.8][s8-8]), which the head parse split. On `get_input`, `get_face` and
11570	  a binding read the head is therefore matched against the level's face
11571	  list, the longest face name that is a prefix of the address followed by
11572	  the end, a `.` or a `[`, and a `Symbol` leaf names the face whole. The
11573	  path selectors parse as before, a field name being an identifier.
11574	  Reserving `.` in face names instead was considered and declined for now:
11575	  the cleaner grammar, but a change to the house style (`input_passthrough`'s
11576	  `sep`, [§14.9][s14-9]'s `"wing.throttle"`, some eighty test faces) that belongs
11577	  with the exported-name audit, not with a fix on an unpushed increment.
11578	
11579	  Annotation (2026-10-01): the decline is final, and the question leaves the
11580	  exported-name audit. Reserving `.` alone would not make the head a parse.
11581	  [§8.6][s8-6] bars only `/`, so a face `gear[1]` beside a vector face `gear` gives
11582	  `"gear[1]"` the two readings `"a.b"` has, and a parsed head needs face
11583	  names to be identifiers, which reverses [D-046][d-046]. The match costs nothing:
11584	  resolution needs the face list for the face's type anyway, and every
11585	  reader resolves its address against a build. No other separator marks
11586	  grouping as the dot does beside an identifier's underscores. Where faces
11587	  `a` and `a.b` both exist the longest wins, and a build warning for a face
11588	  name that is also an address into another face stays addable after a
11589	  release, which a reservation does not.
11590	- Each step is checked at resolution against the type resolved so far. A
11591	  `.name` step needs an isbits struct with that field. An index step needs an
11592	  `SArray`, with one index (linear) or one per dimension. A step never enters
11593	  an opaque leaf (a field handle, a `Symbol`), which is read whole or not at
11594	  all.
11595	- The address is a field of the selector value, never a type parameter. The
11596	  baked read carries the resolved step chain as a type parameter and executes
11597	  it as `getfield` and `getindex` calls unrolled at compile time.
11598	- A store selector takes a field name with at most an index step, since the
11599	  state is flat ([§7.1][s7-1]).
11600	
11601	  Annotation (2026-09-30): the flatness is the continuous tier's. `get_deriv`,
11602	  and `get_state` on a continuous field, take at most an index step; a
11603	  discrete `s` field is any isbits value ([§3.2][s3-2]), and `get_state` on it takes
11604	  the full address, the cold review of increment 57 having found the walk
11605	  already sound there.
11606	- A binding read admits the leaf address as every inspection reader does,
11607	  and the binding register's gather is the family's baked read. The index
11608	  refusal on binding reads goes.
11609	- Diagnostics spell a matrix leaf `m[i,j]`, so an error names a leaf in the
11610	  spelling a selector takes.
11611	- Wiring stays port-granular ([§4.3][s4-3]). A consumer wanting less than a bundle
11612	  destructures it, in its own stage or through an unbundling component that
11613	  takes the bundle and publishes its fields, a candidate for [§13.7][s13-7]'s library.
11614	
11615	**Spec.** [§4.2][s4-2], [§4.3][s4-3], [§14.4][s14-4], [§14.7][s14-7], [§14.10][s14-10], [Appendix B][sB]
11616	
11617	**Rationale.** A bundle port such as `pose = KinPose{T}` is one cell ([D-036][d-036]),
11618	and the family addressed a port whole or by one index into a vector leaf.
11619	[§4.2][s4-2]'s flat namespace and [§4.3][s4-3]'s lazy drilling described a GUI affordance and
11620	promised no addressing surface, and the 2026-09-04 audit read them as one
11621	(`docs/reports/20260904_conformance/a_foundations.md`, 4.3). The remedy [§4.3][s4-3]
11622	offered, publishing a hot field loose beside the bundle, asks the author to
11623	foresee every consumer, which a reusable component cannot. An unbundling
11624	component answers that for wired consumers with no new rule. It does not
11625	answer it for a query. A linearization tap names one scalar, and adding a
11626	component to a model in order to ask a question of it is model surgery. The
11627	leaf address serves the query side alone.
11628	
11629	The state needs none of it. [§7.1][s7-1] keeps it flat, so a store selector takes at
11630	most an index step. [D-094][d-094]'s flatness annotation cited the readers addressing
11631	a field as one leaf; that reason no longer holds, and the state stays flat on
11632	its other grounds. Lifting it is a separate ruling with a write-side question
11633	of its own, how a fragment setting `pose.q` composes with one setting `pose`.
11634	
11635	The spelling is the one the framework already prints. The leaf walk's
11636	diagnostic names are dotted with bracketed indices, so a user pastes an
11637	error's leaf into a selector unchanged. The address lives in the selector
11638	value, so a `reads` or `taps` value is one concrete type however its members
11639	are spelled, and the compiled read specializes once per distinct address,
11640	exactly as it did per distinct index. Folding the index into the string
11641	leaves the family one grammar. A matrix leaf takes `[k,l]` because the
11642	grammar has to print one either way, and the linear `[k]` stays legal as
11643	Julia's own convention. [D-040][d-040] rejected dotted *paths* because a path's last
11644	segment is a port, not a field. The leaf address begins after the port, and
11645	every segment of it is a Julia field or index, so the affordance it suggests
11646	is the true one.
11647	
11648	**Rejected.**
11649	- *Publishing the wanted field loose beside the bundle ([§4.3][s4-3]'s fan-out) as
11650	  the general remedy:* the author must foresee the consumer; kept as an
11651	  optimization for a known hot field.
11652	- *An unbundling component in place of the leaf address:* right for wiring,
11653	  wrong for a query, and unable to reach a root input or a face without
11654	  changing the model.
11655	- *Sub-field wiring:* the port stops being the atomic unit ([D-036][d-036],
11656	  unchanged).
11657	- *A symbol chain before the index, `get_output(path, :pose, :q_eb, 2)`:*
11658	  readable at depth one, noisy below, and it keeps the trailing integer that
11659	  reads as a field at a glance.
11660	- *A keyword path beside the field:* reads worst of the three, and leaves two
11661	  ways to spell one read.
11662	- *Keeping the integer index beside the string:* two grammars in one family,
11663	  where the family's point is one address space.
11664	- *The address as a type parameter of the selector:* every `reads` and `taps`
11665	  value a distinct type, resolution specialized per selector, no runtime
11666	  gain.
11667	- *Nested `NamedTuple`s in the state:* nothing unsound bars them, but nothing
11668	  asks for them either; the tree and flat names serve the cases found, and
11669	  the write side owes a composition rule first.
11670	- *A linear index only, `[k,l]` as a later extension:* the grammar prints a
11671	  matrix leaf either way, and deciding it once is cheaper than revisiting.
