2918	### D-096 — Define the harness writer: `stage!`/`latest`/`step!` duration
2919	
2920	**Status.** ratified
2921	
2922	**Position.** The harness writer ([§12.6][s12-6], [§11.3][s11-3], [§11.2][s11-2]): `stage!(sim, "face" =>
2923	value, ...)` = task-free staging from the calling task into the interactive
2924	writer ([D-044][d-044]'s derived surface) — traced, surface-checked, drained *last* at
2925	the frame top (the explicit hand of code beats a widget interaction; sequencing
2926	within one writer, not cross-device policy), so the mutation doctrine
2927	(staging and control, nothing else) and replay bit-identity hold.
2928	
2929	**Spec.** [§11.2][s11-2], [§11.3][s11-3], [§12.6][s12-6]
2930	
2931	**Rationale.** `latest(sim)` = the current published snapshot, the same
2932	immutable value device handles read; `step!` gains the duration spelling
2933	`t_plus` (whole frames until the boundary time covers the duration, mutually
2934	exclusive with `frames`); together the write/read halves of [D-088][d-088]'s
2935	advance-assert and fly-inspect idioms and the migration path for the suite's
2936	dominant write-`u` → `step!` → assert idiom.
2937	
2938	**Rejected.**
2939	- *A special harness device:* a device with no task is `stage!` with extra
2940	  ceremony.
2941	- *`step!(sim; inputs = …)` drain-from-argument:* a second staging spelling
2942	  with no `run!` analogue.
2943	- *Direct slot pokes from the calling task:* [§2.2][s2-2]/[§12.5][s12-5]'s rejected
2944	  unrecorded-mutation idiom — breaks replay.
2945	- *Leaving reads to device handles or the log:* the log can be off, a handle
2946	  needs a device, and [D-088][d-088]'s "inspect" must be spellable.
2947	- *A public closure-evaluation API:* [§13.5][s13-5]'s rejected cost — an inspection
2948	  *accessor* returning the immutable snapshot is not it.
