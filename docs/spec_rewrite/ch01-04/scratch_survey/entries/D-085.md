2596	### D-085 — Unpack `Tuple`/`NamedTuple` fields as container children
2597	
2598	**Status.** ratified
2599	
2600	**Position.** Container children: `Tuple`/`NamedTuple` fields with
2601	all-component elements unpack as children (`"field/1"`/`"field/key"` path
2602	segments, declaration-order layout); containers are transparent grouping — no
2603	contract, no `connections`, no rate scope.
2604	
2605	**Spec.** [§6.1][s6-1], [§8.5][s8-5], [§8.6][s8-6], [§8.7][s8-7], [§8.8][s8-8], [§14.9][s14-9]
2606	
2607	**Rationale.** Elements are the *parent's* children, wired/exported/rated by
2608	element name; parametric rosters (`Formation{NT <: NamedTuple}`) compose per
2609	instantiation via [§8.8][s8-8] generic holding, wires generated by comprehension
2610	(arity-via-computed-contracts at structure scale; [§14.9][s14-9] swarms and
2611	`at`-mounting consume directly); mixed component/non-component elements = build
2612	error, zero-component containers = inert data, no container nesting (first
2613	cut), empty containers legal, `rates` keys = element names with bare-field-name
2614	uniform-`K` sugar.
2615	
2616	**Rejected.**
2617	- *One-field-per-child + programmatic struct generation:* roster frozen in
2618	  source text; fights the no-macros stance.
2619	- *Homogeneous-`NTuple`-only:* the per-element complexity objection was hollow
2620	  — element types are static either way; named and mixed rosters are the [§14.9][s14-9]
2621	  case, user call.
2622	- *`Vector{C}` children:* runtime-sized, mutable — breaks the immutable tree
2623	  and the type-stable layout.
2624	- *Containers as anonymous assemblies:* a second composition boundary without a
2625	  type — wiring must stay with the parent.
