The framework asks for four functions.
init!(dev)          # per-run resource acquisition — calling task, before spawn (§12.4)
loop(dev, handle)   # the task body: owns its own wait structure
shutdown!(dev)      # per-run resource release — guaranteed on every exit path
unblock!(dev)       # make a blocked loop return (§12.4)
Of the four functions, only loop is mandatory  ( D-366). init!, shutdown! and unblock! are 
optional hooks, each defaulting to a no-op. attach! refuses a device with no loop method 
(DeviceContractMismatch, D-216).
The framework owns everything around the four functions (D-102). The wrapper is the shutdown 
protocol (§12.4) made structural.
init!(dev)                                   # its own bracket, pre-spawn (§12.4): a throw
                                             # here is shutdown! + DeviceCrash by name
task = Threads.@spawn try
    loop(dev, handle)
catch e
    report!(entry, DeviceCrash(e))           # §12.4(6): sim continues, device absent
finally
    shutdown!(dev)                           # any exit path: OS resources released
                                             # no dead-marking: task_state shows the end,
                                             # claims stay, §11.3
end
What shutdown! must tolerate
shutdown! must tolerate a partially initialized device  (D-138). The release guarantee holds on 
the one path outside this wrapper too. The initialization step (§12.4) brackets each init! (D-138). A 
device that threw half-way through acquisition goes straight back to shutdown!, so nothing it did 
manage to open is leaked. The obligation that follows is "close only what is open". That is the same 
defensiveness shutdown! already owes the crash path, where a loop body may die at any point in its 
own life. init! is correspondingly not asked to clean up after itself. The bracket does once, for every 
device, what would otherwise be duplicated in each and enforced in none.
The same tolerance covers a repeated call (D-268). The wrapper runs shutdown! once on every 
exit path. When an operator interrupt (Ctrl-C in an interactive session) reaches run! before its tail, 
run! releases directly, not through a wrapper, each device it never spawned, advancing a cursor 
after each shutdown! returns, and retries from where an interrupt cut it (§12.4, D-268). An interrupt 
landing between a shutdown!'s return and the cursor's advance repeats that call rather than leak the 
device, so each such interrupt adds one call. A shutdown! that closes only what is open is idempotent 
by construction, so a repeated call costs nothing and is never reported.
The tolerance also covers a call with no init! before it (D-268). The initialization step lists each 
device for release before its init! begins, so that no interrupt can leave an initialized device unlisted 
(§12.4, D-268). An operator interrupt landing between the listing and the init! therefore releases a 
device that opened nothing. A shutdown! that closes only what is open does nothing there, and the 
call is never reported.
