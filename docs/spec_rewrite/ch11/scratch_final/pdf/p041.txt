The rule is uniform because the width of a claim (the set of faces a device may write) is a fact 
about one binding, not about a category of writers. A binding is the value passed at attach! that 
makes a device framework-legible. A greedy claim is the unclaimed complement the framework 
computes at attach ( §11.3). It is enumerated and as wide as the root contract (the root's declared 
interface), so keying retention by claim source is rejected ( D-176). Every consumer then handles 
one format instead of two. There is one record format at the trace's edge, no per-record format flag, 
one decoder in the edited-inputs what-if (replay with edited inputs), in disk serialization and in 
human inspection, and one inverse conversion in replay. That work is paid once, up front, off the 
loop (§12.7). The conversion site is the drain and not the staging shim, because the drained tuple is 
the coalesced truth. A shim-side sparse log would need its own merge.
The format's costs are recorded rather than argued away. On the wide writers the conversion is what 
keeps the trace honest. A tuple as wide as the unclaimed surface carrying one edit would otherwise 
make trace size track surface width rather than information. At hundreds of faces, render-rate 
dragging would inflate the trace past the two-orders-below-the-log budget that justifies trace-on-
by-default (D-029). On the dense component the conversion costs about 2×, a position beside every 
value where the positional tuple carried the value alone. That changes no order of magnitude, and 
it leaves the budget (D-029) standing for every writer at once.
The allocation is of the same sort the retention carve-out ( §9.8) already admits. Per boundary (a 
published consistency point) it is smaller than the log's snapshot. The log is the retained sequence 
of published snapshots. A snapshot, the immutable per-boundary publication, is the carve-out's 
standing occupant and the one qualified exception to retains-what-was-already-allocated. The deci-
sion is reversible as pure implementation. The conversion is lossless in both directions, so verbatim 
retention could return as a per-record storage optimization if a marathon-session measurement ever 
asks for it. Such a return would leave the record semantics, the header and the replay path exactly 
as they are.
The header
The trace header is the trace's fixed preamble. A checkpoint is the Model's state at a frame top as one 
value. The header is the checkpoint init! takes at the end of boundary zero (the initialization 
boundary at t₀), after the first snapshot is published (§12.6, D-274). A checkpoint holds the flat buffer 
x, the s and m stores, the whole signal table (the collection of cells holding every produced signal), 
the guard priors, t and t₀, the frame and boundary counters, and the fingerprint (the structural 
layout) and the deployment (D-319). The deployment is the scalar-free artifact the grid parameters 
fix. A prior is an event's stored predicate sample from the previous boundary. The executor's clock 
holds t and t₀, and the Run (the state one run owns, a Simulation field) holds the frame index and 
the boundary ordinal (D-317). The executor is the compiled form of the stage execution order. The 
header holds the stores and the cells of the root inputs (the root component's own input faces) 
as values, never the sparse authored overlay. Replay must survive edits to declared defaults, the 
primary-data doctrine (D-038).
