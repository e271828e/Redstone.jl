The operator interrupt
The wrapper makes one discrimination. An InterruptException is never a DeviceCrash (D-132). The 
operator interrupt is a control-plane stop, not a failure (D-132). The wrapper forwards the control-
plane stop. There is no crash report for what is not a crash, and no should_abort consultation, since 
a stop is already requested.
The author-owned loop body
One device contract means author-owned loop bodies. A framework-owned hook loop would have 
to ask each device what it waits on, which is the rejected taxonomy resurrected as a trait ( D-102). 
Under the author-owned body, every wait structure is ordinary user code composed from handle 
primitives. In the sketches, T16000M is FlightCore's type for the Thrustmaster T16000M joystick, and 
UDPInput is FlightCore's UDP input device type. Telemetry is an illustrative output device type. The 
sketches map data through the binding's map_input and map_output, described below.
function loop(dev=:T16000M, handle)              # timer-driven, full write-set
    while running(handle)
        sleep(dev.Δt_poll)
        stage!(handle, map_input(poll_axes(dev), binding(handle))==.)
    end
end
function loop(dev=:UDPInput, handle)             # source-driven, data-dependent
    while running(handle)
        datum = recv(dev.socket)                 # blocks; unblock! closes the socket
        is_eot(datum) =& return                  # voluntary exit
        try
            stage!(handle, map_input(datum, binding(handle))==.)
        catch e
            is_datum_error(dev, e) =| rethrow()  # a bug → wrapper → DeviceCrash
            report!(handle, MalformedDatum(e))   # garbage → visible, bounded, alive
        end
    end
end
function loop(dev=:Telemetry, handle)            # boundary-driven output
    while running(handle)
        snap = wait_next_snapshot(handle)        # §12.3; returns on stop
        send(dev.socket, map_output(gather(handle, snap), binding(handle)))
    end
end
A bidirectional peer composes both halves itself, with an inner reader task inside its own domain, 
rather than forcing a select engine into the framework. Two idioms are author obligations the 
framework can only teach and diagnose, never force ( Appendix A, D-102). The author must loop 
on running(handle) and must make blocking calls interruptible (unblock!, or timeouts). A forgotten 
predicate check surfaces as DeviceJoinTimeout with the device's name. A stall surfaces as a stale 
heartbeat (§12.2). Liveness timestamps ride inside the handle primitives, which store them in the 
device's own diagnostic cell (§11.8), so the framework observes activity without owning the loop.
FlightCore's device hook should_close dissolves (D-102). A window ✕ or peer EOT is the loop 
body returning, which is §12.4(6)'s case. The wrapper's exit path releases the device's OS resources 
and consults should_abort. Nothing marks the device dead beyond its record. The task has ended,
