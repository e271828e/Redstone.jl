of the channel that carries it. A chattering model (one exhausting its per-frame localization budget) 
or a peer flooding malformed datagrams costs at most sixteen retained values and one integer 
increment per kind per frame, whatever its source does. No writer can starve another, because the 
diagnostic cells are disjoint.
The diagnostic cells are taken at the same drain §11.4 specifies (D-136). The loop performs 
one atomicswap per diagnostic cell at frame top, at the same point and under the same indivisible-
take argument as the staging drain. What the loop swaps in is a shared empty sentinel, so a quiet 
frame swaps the sentinel in and gets the sentinel back. That allocates nothing, and it leaves no load-
only code path that goes untested on healthy runs.
The take also makes publication sound. The binding rule says that nothing reachable from a pub -
lished snapshot is ever written again (§11.2). Because the taken ring is exclusively the loop's before 
it is ever reachable from a snapshot, the binding rule holds by construction. The live accumulator 
is never reachable from a published value.
The heartbeat
The heartbeat rides in the same diagnostic cell, as an atomic timestamp field ( D-136). The device 
task stores it on every loop pass from inside the handle primitives. That way the framework 
observes activity without owning the loop body ( §11.6). The loop acquire-loads the heartbeat 
at publication, when it assembles the status (D-240). There is no separate liveness channel and no 
second registry. A device that is alive is a device whose diagnostic cell carries a recent timestamp, 
and the 2 s staleness threshold ( §12.2) is read against this field. The heartbeat is not a diagnostic 
kind. It is a field, always present, never enumerated in Appendix C.
The published status
The published framework status is a concrete frozen value (D-136). Per writer it carries four 
things beside who. recent is the ring the frame's drain took, carried by the first publication after that 
drain, at most sixteen values per diagnostic cell it takes. The loop's record folds two, its own and 
the Model's (D-317). suppressed is the per-kind counts the ring refused in that drain. totals is the 
cumulative per-writer × per-kind counts since the run began, owned privately by the loop and copied 
into each status. And heartbeat rides beside the task_state the loop reads off its own device Task 
handle at publication (§12.2, D-193). Beside the per-writer records ride the pacer diagnostics (§10.7).
Each per-writer record has this shape.
struct WriterStatus
    who=:String
    recent=:Vector{DiagValue}
    suppressed=:KindCounts
    totals=:KindCounts
    heartbeat=:Union{Nothing,Float64}
    task_state=:Union{Nothing,Symbol}
end
DiagValue is any value of the kinds the channel carries, and KindCounts is the per-kind counter record 
that the allocation rules below describe.
