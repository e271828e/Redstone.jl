The cost supports the default. The trace retains one small sparse record per drained batch (above), 
at drain-rate × device-count. That is tens of MB per hour worst case, two orders of magnitude below 
the snapshot log. There is no sampling and no rolling window (D-029).
11.6 Devices: one authoring contract, no taxonomy
FlightCore's input/output/GUI trichotomy is lock choreography, not modeling. With no lock, the 
protocol the taxonomy encoded has no referent (D-025). A device is an attached participant in the 
periphery (everything outside the loop that exchanges data with it). A device may be input-only or 
output-only, and those are degenerate uses, not framework classes (D-025). A bidirectional network 
peer is one device with one socket and one lifecycle, not two framework devices sharing state. The 
GUI is an ordinary device, the paradigm one, and it uses every capability of the handle below. Its 
one genuine peculiarity, read-modify-write widgets, is not taxonomic (§11.7).
The device handle
Every attached device receives the same handle. The handle carries the two primitive capabilities, 
read and stage, plus control access (observe running, request shutdown) ( D-025). Read returns 
the latest snapshot (the immutable per-boundary publication). It can optionally wait for the next 
boundary (a published consistency point) first (§12.3).
Each attached device has a roster entry (its record in the list of attached devices). A handle outlives 
its roster entry as an object only (D-244). detach! retires the roster entry and the compiled writer 
behind it, but the caller may still hold the handle attach! returned. Its two write primitives, stage! 
and report!, then refuse by name (DeviceContractMismatch, Appendix C). A batch staged there would 
land in a staging cell that no drain reads. A report would land in a diagnostic cell that no frame 
top folds. A batch is a device's staged set of writes. A staging cell is the per-device holding place 
where a pending batch waits between drains. The drain is the frame-top swap that applies staged 
device writes to the root inputs. A diagnostic cell is each writer's bounded ring of diagnostics and its 
heartbeat. A frame is one iteration of the loop. Silence is the hidden-bug class this section tolerates 
nowhere. The read primitives stay legal, since they read the simulation's shared state and nothing 
of the roster entry's (D-244).
The authoring contract
A device's type is a user type subtyping the framework's neutral root, MyDevice =: AbstractDevice 
(D-177). That is one mandatory word, and it costs nothing, because the periphery has no competing 
hierarchy to inherit from. What it buys is attach!'s dispatch gate (D-177).
attach!(sim=:Simulation, dev=:AbstractDevice, new_binding=:AbstractBinding;
        should_abort=:Bool = false)
attach! takes the device with its binding (the value that makes a device framework-legible, described 
below). Its keyword should_abort (the per-attachment failure policy) is covered after the loop bodies 
below.
