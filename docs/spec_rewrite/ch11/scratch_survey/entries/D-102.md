3135	### D-102 — Author-owned device loop inside a framework-owned bracket
3136	
3137	**Status.** ratified
3138	
3139	**Position.** Device authoring contract: author-owned loop body inside a
3140	framework-owned bracket — a device implements `init!(dev)` (per-run resource
3141	acquisition, calling task, pre-spawn), `loop(dev, handle)` (the task body,
3142	owning its own wait structure, composed from handle primitives),
3143	`shutdown!(dev)` (guaranteed via the wrapper's `finally`) and optional
3144	`unblock!(dev)`.
3145	
3146	**Spec.** [§11.1][s11-1], [§11.6][s11-6], [§12.4][s12-4], [Appendix A][sA]
3147	
3148	**Rationale.** The wrapper is try/catch/finally with `DeviceCrash` on catch and
3149	claims-release/detach on every exit; `should_close` dissolves into the loop
3150	body returning (voluntary exit); the GUI implements the same contract, called
3151	inline on the calling task ([§11.1][s11-1]); heartbeat timestamps ride inside handle
3152	primitives, so liveness needs no loop ownership; the two author obligations
3153	(`running(handle)` predicate, interruptible blocking) are taught ([Appendix A][sA])
3154	and diagnosed (`DeviceJoinTimeout`, stale heartbeat), never forced.
3155	
3156	**Rejected.**
3157	- *Framework-owned hook loop (FlightCore's shape):* its eight hooks were never
3158	  sufficient alone, the loop came in three taxonomy-carried flavors; one kind
3159	  would force a declared wait kind = the taxonomy as a trait; the bidirectional
3160	  peer needs two waits a hook loop cannot serve without a select engine; the
3161	  GUI fits no hook set.
3162	- *A two-hook middle (`wait_datum` + `process`):* same failures, softer.
