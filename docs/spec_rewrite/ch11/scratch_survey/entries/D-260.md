10165	### D-260 — Trim the run to what lasts it and retire the trace register
10166	
10167	**Status.** ratified
10168	
10169	**Position.** A `Run{T}` holds what lasts from one door to the next and the
10170	state that evolves in between. The stop policy, the origin and the drain's
10171	bookkeeping leave it.
10172	
10173	- `Run{T}` is a mutable struct of four fields: `const log`, `const trace`
10174	  (`nothing` under the trace switch), `feed` (the attached recording, or
10175	  `nothing`) and `termination`. `init!` and `replay!` construct one and
10176	  rebind `sim.run`; nothing else rebinds it. `live!` and the halt at the
10177	  recording's end write `feed`; the loop's tail writes `termination` once.
10178	  `closed(run)` is unchanged.
10179	- The input mode is read, not stored. `mode(sim)` is `:replay` while a feed
10180	  is attached and `:live` otherwise. A change of mode is a write to the run,
10181	  not a change of run.
10182	- The stop policy is the advance's argument. `run!`, `replay!` and `step!`
10183	  build it, pass it to the loop and to the record's assembly, and drop it.
10184	  The termination record is the policy's one lasting home.
10185	- The origin `t₀` is not a run field. The clock holds it, `init!` and
10186	  `replay!` set it, and the trace header records it. It is a `Float64`, like
10187	  `h` and `t_end`; the clock's `t` stays in the deployment's scalar.
10188	- `TraceRegister` retires. The drain thunks close over the run's trace and
10189	  are recompiled at every door and roster change, as they already were. The
10190	  frame ordinal a record carries is the trace's own `frames`, incremented at
10191	  the top of the drain. The current writer set's index range is local to the
10192	  recompile. The trace switch rides on the run: a run built under
10193	  `trace = false` has no trace.
10194	
10195	Supersedes [D-255][d-255]'s first bullet, its "the register keeps its cursor fields
10196	and the replay feed" clause and its "rebound on `Run.policy`" clause, and
10197	[D-256][d-256]'s "the trace switch on the register the plane holds". [D-218][d-218]'s mode,
10198	"a register the caller can read", is `mode(sim)`, unchanged as an
10199	observable.
10200	
10201	**Spec.** [§11.5][s11-5], [§12.6][s12-6], [§12.7][s12-7], [§13.5][s13-5], [Appendix B][sB]
10202	
10203	**Rationale.** [D-255][d-255] classed the run's fields by whether the door fixed them
10204	or the loop advanced them. The policy fit neither. An advance declares it,
10205	the loop reads it as an argument, and the field on the run was written at
10206	every `run!` and `step!` only so two readers without the argument, the t*
10207	sampling read and the record's assembly, could reach it. It does not shape
10208	the trajectory, since a stepped and a run simulation are bit-identical
10209	whatever each call declared ([§12.6][s12-6]), and only the terminating advance's
10210	policy is ever read afterwards, off the record. `t₀` on the run had no
10211	reader: every consumer of the origin, the frame count, the grid time and the
10212	header capture, read the clock's. `mode` was `const`, so a flip rebuilt the
10213	run, but a flip keeps the log and the trace, which is what makes it the
10214	same run; and the feed was attached exactly while the mode was `:replay`,
10215	an invariant the code guarded with an internal throw. One field states
10216	both. Of the register's five fields, the trace duplicated the run's, the
10217	frame was a courier to the thunk that the trace's own drain count already
10218	carries, the writer range was read only where it was written, and the
10219	switch is a fact about the run's trace. The thunk cannot take the ordinal
10220	as an argument: it is called through an untyped field, and a boxed `Int`
10221	would allocate on the frame path ([§9.8][s9-8]). Closing over the trace, a mutable
10222	object, keeps the ordinal reachable at no cost. The origin's type follows
10223	the grid's. `h` and `t_end` are `Float64` already, and a `Dual` origin with
10224	a nonzero partial, a start-time perturbation, has no reader in the design.
10225	A `Float64` origin also lets `init!` take `t0 = 0.25` on a `Dual`
10226	simulation, which a `T`-typed keyword refused.
10227	
10228	**Rejected.**
10229	- *A run per advance, owning its policy:* the log and the trace span
10230	  advances, so consecutive runs would share them and own neither; and an
10231	  advance that halts at a frame top leaves nothing of its policy behind.
10232	- *An immutable `Run` rebuilt at every flip and at the close:* the flips and
10233	  the close keep the log and the trace, so a rebuild there spells "the same
10234	  run" as a new object.
10235	- *The termination record as `run!`'s return value:* the errored path
10236	  rethrows and returns nothing, `step!` already returns the frame count, and
10237	  [D-060][d-060] chose state over exception so a stopped simulation answers from any
10238	  task and at any later time.
10239	- *`mode::Symbol` beside the feed:* two fields that must agree, and the
10240	  throw that guarded them.
10241	- *The `Run` holding the `Simulation`:* every run would be a live handle to
10242	  the executor's buffers, so a stale run after a warm restart would advance
10243	  the new trajectory under the old run's name, an invariant with no
10244	  enforcer ([§9.2][s9-2]).
10245	- *The frame ordinal as the thunk's argument:* a boxed `Int` per drain per
10246	  writer, on the frame path.
