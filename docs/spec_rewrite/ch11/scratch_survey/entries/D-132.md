4133	### D-132 — Treat operator interrupt (Ctrl-C) as a control-plane stop, not a failure
4134	
4135	**Status.** ratified
4136	
4137	**Position.** The operator interrupt (Ctrl-C) is a control-plane stop, not a
4138	failure. It joins `t_end`, `stop_on` and the GUI/handle/code stop among
4139	[§12.4][s12-4](1)'s initiation sources: the run completes the current boundary,
4140	publishes the final snapshot, takes the ordinary graceful tail and ends
4141	`stopped` — boundary-consistent, serviceable by the [§14][s14] services, resumable by
4142	the next `run!`.
4143	
4144	**Spec.** [§10.7][s10-7], [§11.6][s11-6], [§12.4][s12-4](1), [§12.4][s12-4](3), [§12.4][s12-4](5), [§13.4][s13-4], [§13.5][s13-5], [§14][s14], [§14.8][s14-8],
4145	[Appendix C][sC]
4146	
4147	**Rationale.** **Boundary masking is normative**, not an implementation hint:
4148	because `InterruptException` is asynchronous, the loop masks delivery across
4149	the boundary macro-sequence (Julia's `disable_sigint`, a sigatomic counter
4150	increment per frame) and takes the deferred raise at the unmask points — frame
4151	top, wait and pause blocks — all boundary-consistent; the
4152	`stopped`-with-consistent-stores guarantee depends on it. Two discrimination
4153	clauses fall out: [§13.4][s13-4]'s catch site never wraps an `InterruptException` in
4154	`StepError` (routes it to the stop path; unreachable in practice under masking,
4155	kept defensively), and [§11.6][s11-6]'s device wrapper never turns one into `DeviceCrash`
4156	— in the spawned-loop topology Ctrl-C lands in the calling task's inline device
4157	loop body (the GUI), which forwards the stop and exits through the ordinary
4158	`running(handle)` predicate, no `should_abort` consultation. A **second**
4159	interrupt during the tail collapses the remaining device joins immediately —
4160	[§12.4][s12-4](5)'s abandonment path taken at once, devices still named — and the run
4161	still ends `stopped`; escalation shortens the tail, never reclassifies the run,
4162	and cannot repair [§12.4][s12-4](5)'s honest asymmetry (nothing can abandon the task
4163	`run!` stands on). Scope is the **interactive session**: outside the REPL
4164	Julia's default `exit_on_sigint(true)` kills the process on SIGINT first, the
4165	framework flips nothing process-global, and unattended runs rely on
4166	`t_end`/`stop_on` as they already must. The termination record tags the stop
4167	source ([§13.5][s13-5]), distinguishing it from `t_end`, `stop_on` and a
4168	programmatic/GUI stop, with no new diagnostic kind; `UnboundedRun` ([Appendix C][sC])
4169	names it as the sanctioned escape from the configuration it warns about; and
4170	the services need no story of their own — an interrupt during a long `trim!`
4171	unwinds an ordinary call over per-invocation scratch stores, no commit having
4172	happened ([§14.8][s14-8]). Precedent correction, recorded because it is easy to miscite:
4173	FlightCore's `interrupt!` (iodevices.jl:36, its one override closing UDPInput's
4174	socket at shutdown) is a per-device unblocking hook — the direct precedent of
4175	[§12.4][s12-4](3)'s `unblock!`, not of this path; FlightCore has no
4176	`InterruptException`/SIGINT handling anywhere.
4177	
4178	**Rejected.**
4179	- *Treating the interrupt as a runtime failure — the `StepError` path an
4180	  unguarded Ctrl-C takes today:* destroys the session it means to pause:
4181	  terminal `errored`, no services, no resume, and with mid-boundary delivery,
4182	  dirty stores.
4183	- *Pausing instead of stopping:* does not return the prompt in the synchronous
4184	  deviceless case — the very run that has no other escape — and a paused run is
4185	  not serviceable.
4186	- *A public `interrupt!` entry point:* redundant: the control plane already
4187	  carries the stop, and a function call is available to code that could have
4188	  called `stop` anyway — the FlightCore name would also import an unrelated
4189	  per-device meaning.
4190	- *Process-global `exit_on_sigint(false)` set by the framework:* changing
4191	  process-wide signal behavior behind the user's back, and wrong for the
4192	  unattended runs that want the kill.
4193	- *Escalation reclassifying the run as `errored`:* nothing is broken — the
4194	  operator asked twice for the same stop.
