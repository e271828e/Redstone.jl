3337	### D-108 — Gate stopped-sim services by input-derived lifecycle preconditions
3338	
3339	**Status.** ratified
3340	
3341	**Position.** Service lifecycle preconditions: every stopped-sim service
3342	requires a non-running simulation, pause included (the [D-106][d-106] doctrine — the
3343	loop owns the stores between drains); within the stopped states legality
3344	follows each service's inputs — `capture` requires `initialized`/`stopped`
3345	(reads committed stores), `init!` and `trim!` are additionally legal from
3346	`built` (inputs are authored conditions; trim's scratch world comes from
3347	`override(baseline, condition(guess))`, never the sim's stores), `linearize`
3348	inherits `capture`'s precondition with the defaulted operating point and
3349	`init!`'s with an explicit `about`.
3350	
3351	**Spec.** [§11.3][s11-3], [§13.6][s13-6], [§14][s14]
3352	
3353	**Rationale.** `errored` is terminal for all four ([D-059][d-059]) — a captured
3354	condition is indistinguishable from a healthy one once produced, so
3355	`capture(errored)` would be resurrection with extra steps and defaulted
3356	`linearize(errored)` a warn-but-assign re-entry; post-mortem stores/log/trace
3357	stay readable as diagnostics, never as condition values; one kind
3358	`ServiceLifecycle` (operation, current status, legal statuses) shared with
3359	`attach!`/`detach!`-while-running — closing the kind [D-106][d-106]'s gating text
3360	lacked.
3361	
3362	**Rejected.**
3363	- *Folding `MissingInit` into `ServiceLifecycle`:* distinct cases: a
3364	  missing prior step pointing forward to `init!` vs. an operation illegal in
3365	  the current state — different messages, different tests.
3366	- *Tolerating `capture` on `errored` for diagnostics:* the produced condition
3367	  value is healthy-looking by construction; diagnostic reads need no condition
3368	  value.
3369	- *Gating `trim!`/`init!` out of `built`:* their inputs are authored — the gate
3370	  would forbid mechanically sound calls.
