2838	### D-093 — Spawn device tasks per run, not per attach
2839	
2840	**Status.** ratified
2841	
2842	**Position.** Device tasks are per-run artifacts ([§11.1][s11-1], [§12.4][s12-4], [§12.6][s12-6]): `run!`
2843	spawns one task per roster entry after per-run device `init!` (resource
2844	acquisition per run — FlightCore's create-a-new-socket-each-`init!` in
2845	network.jl the precedent; `attach!` never spawns — one semantics, register,
2846	[D-106][d-106]).
2847	
2848	**Spec.** [§11.1][s11-1], [§11.6][s11-6], [§12.2][s12-2], [§12.3][s12-3], [§12.4][s12-4], [§12.6][s12-6], [§13.4][s13-4]
2849	
2850	**Rationale.** [§12.4][s12-4] joins all tasks at every stop with `shutdown!` releasing
2851	OS resources; what persists across `stopped → init! → run!` is the roster entry
2852	(binding, claims, stable device id); spawn-inside-`run!` replaces the start
2853	gate, and first-boundary synchronization is [§12.3][s12-3]'s counter-plus-condition
2854	predicate wait; `should_close` and the [§12.2][s12-2] liveness heartbeat are run-scoped,
2855	unplug-while-stopped surfaces as the next run's device-`init!` failure. The GUI
2856	is the one rostered device *without* a spawned task — CImGui pins rendering to
2857	the calling task, so the loop is the movable piece: with a calling-task device
2858	rostered the loop moves to a spawned task for the run — roster-derived, `gui =
2859	true` mere ensure-rostered sugar ([D-109][d-109]) — otherwise the loop runs on the
2860	calling task (preserving [§13.4][s13-4]'s synchronous rethrow and inline threading of
2861	parallel batch sweeps); `run!` blocks its caller either way. Stepping sessions
2862	are deviceless by construction (`attach!` registers only, tasks appear at the
2863	next `run!`); the write/read paths while stepping are [D-096][d-096]'s harness writer;
2864	`init!` discards staged batches along with trace and log.
2865	
2866	**Rejected.**
2867	- *`Event` start gate "as today":* [§12.3][s12-3]'s rejected primitive — the `io_start`
2868	  reset race, re-imported for the re-run cycle [§12.6][s12-6] newly supports.
2869	- *Persistent tasks parked across stops:* `while running(handle)` false from
2870	  the first iteration; contradicts [§12.4][s12-4]'s guaranteed `finally shutdown!`;
2871	  gives liveness and `should_close` no meaning while stopped.
2872	- *Task handles or lifecycle state in the roster:* mixes mutable lifecycle into
2873	  [D-087][d-087]'s immutable roster value.
2874	- *Always-spawned loop task FlightCore-style:* uniform topology whose only
2875	  beneficiary is the GUI case: costs the [§13.4][s13-4] synchronous rethrow —
2876	  `TaskFailedException` wrapping — inline `@threads` composability of batch
2877	  sweeps, and direct interrupt delivery.
2878	- *GUI as a genuinely spawned task pinned to thread 1:* falsifies [§12.2][s12-2]'s
2879	  cannot-fail-to-be-scheduled argument; buys nothing CImGui permits.
