7070	### D-193 — Keep per-writer liveness on one timestamp plus task state
7071	
7072	**Status.** ratified
7073	
7074	**Position.** Per-writer liveness keeps the diagnostic cell's **single** atomic
7075	heartbeat timestamp ([§11.8][s11-8]'s mechanism untouched); the published per-writer
7076	status gains `task_state`, read by the loop from its own device `Task` handles
7077	at publication; [§12.2][s12-2]'s "last-staged and last-read wall time" split is dropped.
7078	
7079	**Spec.** [§11.8][s11-8], [§12.2][s12-2]
7080	
7081	**Rationale.** [§11.8][s11-8] gives each cell a bounded accumulation plus one atomic
7082	liveness timestamp the device task stores on every loop pass, while [§12.2][s12-2]'s
7083	published status promised "last-staged and last-read wall time, task state" —
7084	two timestamps plus a task state that a single store-on-every-call timestamp
7085	cannot produce. Only one of the three is a genuine cell field: the loop already
7086	owns the device `Task` handles and can read their state where it publishes, so
7087	`task_state` costs the cell nothing. [§12.2][s12-2]'s "the per-writer cell and nothing
7088	besides, specified in full by [§11.8][s11-8]" is qualified to admit those handles.
7089	
7090	**Rejected.**
7091	- *The two-timestamp decomposition — a three-field liveness record in the cell,
7092	  staged and read separated:* its signal is weakest exactly where it would fire,
7093	  a rare-data device legitimately parked in a blocking read showing a stale
7094	  last-staged (the case [§12.2][s12-2]'s loose 2 s threshold exists to tolerate), and it
7095	  grows the cell [§11.8][s11-8] deliberately keeps minimal.
