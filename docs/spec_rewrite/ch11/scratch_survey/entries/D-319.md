13828	### D-319 — Split the checkpoint into the `Model`'s state and the run's cursor, and put the services on the `Model`
13829	
13830	**Status.** ratified
13831	
13832	**Position.** A `ModelState{T}` is a `Model`'s state as one value, and a
13833	`Checkpoint` is a nominal `ModelState` beside the run's frame index and
13834	boundary ordinal. `checkpoint`, `restore!`, `trim!` and `linearize` are doors
13835	of the `Model`, and their simulation methods gate on the lifecycle and
13836	compose the model's.
13837	
13838	- `ModelState{T}` holds every field the former `Checkpoint{T}` held but
13839	  the two counters, nine in all, `x`, `s`, `m`, `table`, `prior`, `t`, `t₀`,
13840	  `deployment` and `layout`. `Checkpoint` holds `state::ModelState{Float64}`, `frame::Int`
13841	  and `boundary::Int`, and it has no scalar parameter. A cursor belongs to a
13842	  trajectory, and only a nominal model has one, so a `Checkpoint` is nominal
13843	  by type, as `Trace` and `Run` are ([D-317][d-317]).
13844	- `checkpoint(model) → ModelState` is legal at `:consistent` with the clock
13845	  on a grid top. At `:built` or `:inconsistent` it is refused as
13846	  `ServiceLifecycle` with `op = :checkpoint` and `legal = [:consistent]`,
13847	  and with the clock off the grid as `CheckpointMidFrame`, naming the frame
13848	  the clock sits inside. `restore!(model, model_state; hooks = NoHooks())`
13849	  takes the claim's gate, then checks the fingerprint and the grid. It
13850	  collects every mismatch, `CheckpointMismatch` and `CheckpointMidFrame`
13851	  alike, into one throw before any write. The grid check asks that the
13852	  state's `t` be `t₀ + k·h` in the state's scalar, for `k` the frame the
13853	  clock sits inside by `_frames_to`, and a state before its `t₀` falls at
13854	  frame 0. The door then copies the state back, calls `settled!(hooks)` and
13855	  writes `:consistent` last. It has no status gate.
13856	- `checkpoint(sim) → Checkpoint` keeps its lifecycle gate and its mid-frame
13857	  test, and wraps `checkpoint(sim.model)` with the run's frame index and
13858	  boundary ordinal. `restore!(sim, cp::Checkpoint; kw…)` makes the same
13859	  grid check on `cp.state`, collected with the fingerprint's.
13860	  `restore!(sim, model_state::ModelState{Float64}; kw…)` is the door a state
13861	  prepared on a standalone model takes into a simulation ([§9.2][s9-2], [D-318][d-318]). It
13862	  makes the checkpoint form's lifecycle, recording and fingerprint checks,
13863	  and the grid check every restore door makes. That check takes `k` as the
13864	  frame the state's clock sits inside, by the frame arithmetic
13865	  `checkpoint(model)` uses (`_frames_to`), and refuses a state with
13866	  `t ≠ t₀ + k·h` as `CheckpointMidFrame` at frame `k`. A state before its own
13867	  `t₀` is refused the same way at frame 0. The same `k` is the frame the
13868	  fresh trajectory opens at, the restored boundary published under ordinal 0
13869	  and the run's ordinal reading 1 after it, as `init!` leaves it.
13870	- A bare state taken at another scalar is refused by dispatch.
13871	  `restore!(::Simulation, ::ModelState{T})` and
13872	  `restore!(::Model{T}, ::ModelState{S})` throw `CheckpointMismatch` with
13873	  `what = :scalar`, the state's scalar expected and the target's found, and
13874	  the message names a `Model`.
13875	- `trim!(model, problem; baseline, t0 = 0.0, backend = LevenbergMarquardt())`
13876	  and `linearize(model, taps; about = nothing, t0 = nothing, width = 8)`
13877	  take a `Model{Float64}`, and each scratch half is a `Model` materialized
13878	  from its deployment ([D-282][d-282]). `trim!` takes the claim's gate before any
13879	  check, since it commits, and commits through the model's own `init!`.
13880	  `linearize` is a read and takes no claim gate, and its default operating
13881	  point is `checkpoint(model)` behind a `ServiceLifecycle` that names
13882	  `linearize`. The simulation's `trim!` and `linearize` keep their lifecycle
13883	  gates and compose the model's solve and query. `trim!(sim, …)` commits
13884	  through `init!(sim, …)`, and `linearize(sim, …)` takes its default point
13885	  from `checkpoint(sim)`.
13886	- `trim!` and `linearize` on a `Model{T}` at any `T` other than `Float64`
13887	  throw `ArgumentInvalid` with reason `:non_nominal` and the value
13888	  `Model{T}`. The `Model{Float64}` methods are more specific and win.
13889	- `trim.jl` and `linearize.jl` name no `Simulation` once their methods take
13890	  a model, so they are included after `frame.jl` and before `sim.jl`.
13891	- The grid arithmetic the model layer reads, `_frame_slack`, `_frames_to`
13892	  and `_frame_at`, lives in `frame.jl` beside `_grid_time`.
13893	
13894	**Spec.** [§9.2][s9-2], [§12.6][s12-6], [§14][s14], [§14.5][s14-5], [§14.8][s14-8], [§14.10][s14-10], [Appendix B][sB], [Appendix C][sC]
13895	
13896	**Rationale.** The checkpoint fused the model's state with the trajectory's
13897	cursor. A `Model{Dual}` can checkpoint and restore without ever having a
13898	cursor, since only a simulation's run counts frames and boundaries. The
13899	services likewise need only the model's pair, the deployment and the
13900	executor, so they take the `Model{Float64}` that holds the operating point,
13901	and a simulation is one holder of it among others. A cursor exists only on a
13902	nominal trajectory, so the type that carries one needs no scalar parameter.
13903	
13904	The two refusals of `checkpoint(model)` mirror the simulation's. [§12.6][s12-6] makes
13905	a checkpoint the state at a frame top, and [§14][s14] says an errored state may not
13906	become one. A model's `:inconsistent` is the simulation's `errored`, and a
13907	model at `:built` has run no boundary zero. The model's `restore!` takes no
13908	status gate, because restoring into a `:built` twin is the door's use.
13909	`checkpoint` on either level refuses an off-grid read, so only a hand-built
13910	state is off the grid. The restore doors already guard against a hand-built
13911	state through the fingerprint, and the grid check is the same class of guard.
13912	
13913	The simulation's `trim!` cannot forward whole to the model's. Its commit is
13914	`init!(sim, …)`, whose run opening and trace header bracket the model's
13915	`init!`, and the commit's outcome is decided only after the solve. So the
13916	solve is factored out of the commit, and each level hands the verdict its
13917	own `init!`. `linearize` splits the same way, so the simulation's default
13918	point and its mid-frame refusal stay the simulation's.
13919	
13920	A standalone model publishes nothing, so a state carried from one has no
13921	trajectory whose ordinals could continue. The bare-state door opens a fresh
13922	trajectory at the state's grid position, in `init!`'s shape. The restored
13923	boundary publishes under ordinal 0, and the run's counter reads 1 after it.
13924	
13925	`checkpoint(model)` reads the frame the clock sits inside, so the grid
13926	arithmetic moves beside `_grid_time`. A call resolves at runtime whatever the
13927	include order, but arithmetic the model layer reads belongs with the frame.
13928	The `Model` block of [Appendix B][sB] places the stepping primitives outside
13929	the API and outside the claim's gate, and `apply!` outside the API but inside the
13930	gate, since [D-318][d-318] refuses it on a claimed model.
13931	
13932	**Rejected.**
13933	- *A parametric `Checkpoint{T}`:* a cursor is a nominal trajectory's, and a
13934	  model at another scalar has none to carry.
13935	- *A `getproperty` forward from `Checkpoint` to its state:* it hides the
13936	  split the type exists to show.
13937	- *`ModelState` carrying the counters:* a model has no trajectory.
13938	- *The simulation's `trim!` forwarding whole to the model's:* the commit
13939	  would run through the model's `init!` with no run opened and no header
13940	  taken, the wedge [D-318][d-318] closed.
13941	- *A status gate on the model's `restore!`:* restoring into a `:built` twin
13942	  is its use.
13943	- *The carried state's boundary ordinal continuing from its frame index:*
13944	  nothing published those boundaries.
13945	- *A claim gate on `linearize`:* a pure query reads the model as `port`
13946	  does.
