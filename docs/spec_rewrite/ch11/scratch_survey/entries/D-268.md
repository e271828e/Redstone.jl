10924	### D-268 — Pause verbs on the simulation, and the interrupt's remaining windows
10925	
10926	**Status.** ratified
10927	
10928	**Position.** The pause is spelled `pause!(sim)`, `resume!(sim)` and
10929	`paused(sim)`, and the operator interrupt is settled at the four places
10930	[§12.4][s12-4]'s masking left open.
10931	
10932	- `pause!` and `resume!` are legal from any task in any lifecycle state; the
10933	  loop consults the flag at frame top and inside its wait and pause blocks;
10934	  `step!` blocks while paused. The tail clears the flag beside the sticky
10935	  stopped status, and no run start clears it. The handle carries no pause.
10936	- A deferred interrupt raised at the unmask point yields to a stop face the
10937	  frame's publication found holding: the face is the recorded source, and
10938	  the interrupt sets the stop word only where none held.
10939	- An `InterruptException` inside a device's `init!` is the operator's stop,
10940	  not that device's crash: the bracket runs `shutdown!`, sets the
10941	  `:interrupt` stop, reports no `DeviceCrash` and spawns no task; the other
10942	  entries still initialize and the run ends at its first frame top.
10943	- The tail's bookkeeping after the joins runs under the mask; a raise
10944	  deferred to its end propagates raw out of `run!`, the simulation already
10945	  terminal.
10946	- `run!` discriminates [§13.4][s13-4]'s two dispositions by the roster: empty is
10947	  unattended and rethrows, non-empty logs the rendered error and returns
10948	  with the lifecycle `errored`. `step!` always rethrows.
10949	- (Amended 2026-09-30, with the three windows around `run!`'s interrupt
10950	  arm.) `shutdown!` may run more than once. The arm releases the
10951	  calling-task entry itself when its wrapper never recorded the release, and
10952	  an interrupt landing between the wrapper's `shutdown!` and that record runs
10953	  it again. The arm's own release can be cut the same way, so each such
10954	  interrupt adds one call. [§11.6][s11-6]'s "close only what is open" makes a
10955	  repeated call harmless, and a leaked device would not be.
10956	- (Amended 2026-10-01, with the init bracket's escape.) `shutdown!` may run
10957	  on a device whose `init!` never began. The bracket lists each entry for
10958	  release before its `init!`, so an interrupt that escapes the bracket finds
10959	  every device that began initializing and that the bracket has not itself
10960	  released. One landing between the listing and
10961	  the `init!` releases a device that opened nothing. [§11.6][s11-6]'s "close only
10962	  what is open" makes that call harmless, and listing after `init!` would
10963	  leak the device whose `init!` had just returned.
10964	- (Amended 2026-10-01, with the lost loop failure.) An interrupt after a
10965	  frame's throw never displaces it. `run!`, `replay!` and `step!` store the
10966	  loop's throw before anything can cut its handling, and the masked
10967	  bookkeeping builds the `LoopError` from the store, so the run ends
10968	  `errored`. An interrupt that cuts the handling itself propagates raw,
10969	  [§13.4][s13-4]'s disposition skipped and the record written.
10970	
10971	**Spec.** [§11.6][s11-6], [§12.1][s12-1], [§12.4][s12-4], [§13.4][s13-4], [Appendix B][sB]
10972	
10973	**Rationale.** [§12.1][s12-1] named the pause as a control-plane field and [§12.4][s12-4] built
10974	the interrupt on masking, but neither spelled the verbs, and the code built
10975	the stop word and the two defensive discriminations of [D-132][d-132] without the
10976	pause or the mask. Building them raised four questions the text did not
10977	answer, each small and each a trap if answered by default.
10978	
10979	The verbs follow the stop's grammar, `stop!(sim)` beside `stop!(handle)`,
10980	and the reader follows `running` and `closed`, bare predicates the API
10981	already spells. The pause stays off the handle because [§11.6][s11-6] lists the
10982	handle's control access as observe-running and request-stop, and the one
10983	device that presses pause is the GUI, whose authoring surface [§11.7][s11-7] defers.
10984	
10985	Clearing the flag in the tail rather than at a run's start is the one
10986	disposition that both removes the trap and keeps a `pause!` before `run!`
10987	meaningful. A run that stopped while paused, under the alternative, would
10988	hand the next run a first frame top it never leaves.
10989	
10990	The face-before-interrupt order is [§13.5][s13-5]'s consultation order applied to the
10991	raise's actual position: the deferred raise lands after the frame's
10992	publication, where the stop faces are read, and before the next frame top,
10993	where the stop word is. Recording the face keeps the order one rule.
10994	
10995	The init bracket's arm mirrors the wrapper's ([D-132][d-132]). Without it a Ctrl-C
10996	during a slow `init!` would land the run `errored`, since the bracket sits
10997	outside the frame loop's catch and its throw would reach `run!`'s outer
10998	catch as a loop failure. The masked bookkeeping closes the last window: a
10999	raise inside the outermost `finally` would leave the lifecycle `running`
11000	with no run behind it, and every service refuses that state.
11001	
11002	The roster is the discriminator because [§12.6][s12-6] defines the unattended run as
11003	the deviceless one and [§13.4][s13-4]'s rethrow presupposes it. The discrimination
11004	sits in `run!` alone since `step!` is deviceless by construction. A probe
11005	under `Base.exit_on_sigint(false)` with `kill(getpid(), SIGINT)` confirmed
11006	the mechanism the entries rely on: a signal inside `disable_sigint` is held
11007	through a `sleep` and raises at the unmask, and one inside a `wait` on a
11008	`Threads.Condition` raises in the wait with the lock released.
11009	
11010	Annotation (2026-09-26): a frame that throws while an interrupt is pending
11011	ends `errored` under its own `StepError`, the cause wrapped under the mask
11012	and the pending interrupt consumed at the catch on its way out ([§12.4][s12-4], [§13.4][s13-4]). Building the mask
11013	showed that both naive shapes, the mask begun outside the frame's `try` and
11014	the unmask in a `finally`, lose the frame's error to the deferred raise and
11015	would end the run `stopped` over a half-written boundary.
11016	
11017	Annotation (2026-09-26): two rulings the cold review raised. Julia's forced
11018	throw after repeated SIGINTs reaches [§13.4][s13-4]'s defensive arm inside the mask,
11019	so the arm is reachable; its disposition is `stopped` with the frame
11020	abandoned, the published record consistent and the stores possibly
11021	mid-boundary until the next `init!`, on boundary zero's precedent ([§12.4][s12-4]).
11022	And `replay!` discriminates the two dispositions by the roster as `run!`
11023	does: the reasoning against `isinteractive()` applies unchanged, and the
11024	deviceless reproduction still rethrows ([§13.4][s13-4]).
11025	
11026	Annotation (2026-10-02): amended by [D-269][d-269]. The loop reads the control
11027	plane, the pause flag included, at frame top alone; the pause block is the one
11028	wait woken at once.
11029	
11030	**Rejected.**
11031	- *`pause!(sim, flag::Bool)` as one verb:* two verbs read at the call site
11032	  and match `stop!`; a Boolean argument spells the un-pause as a negation.
11033	- *A pause on the handle now:* [§11.6][s11-6]'s handle contract does not carry it,
11034	  and the only issuer is the deferred GUI; adding it later costs one method.
11035	- *Clearing the pause at a run's start, as the stop word is:* removes the
11036	  start-paused spelling without removing anything the tail's clearing does
11037	  not.
11038	- *`step!` ignoring the pause:* a second consultation rule for one frame
11039	  loop, and [§12.6][s12-6]'s bit-identity claim rests on the loop being one code.
11040	- *Recording the interrupt over a holding face:* contradicts [§13.5][s13-5]'s order,
11041	  under which the face was consulted first.
11042	- *Reporting an interrupt inside `init!` as `DeviceCrash`:* [D-132][d-132]'s grounds;
11043	  and with `should_abort` clear the run would start with the device dead and
11044	  the operator's stop lost.
11045	- *Leaving the tail's bookkeeping unmasked:* a lifecycle stuck at `running`
11046	  with every service refusing is a bricked session, the outcome [D-132][d-132] exists
11047	  to prevent.
11048	- *Swallowing a raise deferred past the bookkeeping:* the operator asked,
11049	  and the simulation being terminal costs the raise nothing.
11050	- *`isinteractive()` as the discriminator:* a deviceless run in the REPL
11051	  would then hide its failure behind a log line, and a rostered device in a
11052	  script would rethrow past the tail the devices already took; the roster
11053	  states what the glossary defines.
11054	- *Retrying the failure's handling so that an interrupt cutting it is
11055	  swallowed (2026-10-01):* the run is already `errored` with the cause on its
11056	  record, so the raw raise costs the log line or the rethrow alone, and a
11057	  retrying `try` there is machinery for that alone.
