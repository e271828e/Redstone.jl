4536	### D-138 — Make device `init!` an explicit, bracketed step of the run-start protocol
4537	
4538	**Status.** ratified
4539	
4540	**Position.** Device `init!` becomes an **explicit step of the [§12.4][s12-4] protocol**,
4541	taken at the top of a run — once per roster entry, in attachment order, on the
4542	calling task, pre-spawn — with **each call in its own bracket**: on a throw the
4543	framework calls `shutdown!(dev)` on the failing device right there, reports
4544	`DeviceCrash` by name and marks it dead, no task being spawned.
4545	
4546	**Spec.** [§11.1][s11-1], [§11.3][s11-3], [§11.6][s11-6], [§11.8][s11-8], [§12.2][s12-2], [§12.4][s12-4], [§13.5][s13-5], [§14][s14], [§14.6][s14-6], Appendices
4547	A/B/C/D
4548	
4549	**Rationale.** Release is therefore **unconditional**, which is what makes
4550	[§11.6][s11-6]'s "guaranteed on every exit path" and [§12.4][s12-4]'s "`shutdown!` has released
4551	each device's OS resources" true of the one path outside the wrapper, and it
4552	carries a **new taught obligation** ([§11.6][s11-6], [Appendix A][sA]): `shutdown!` must
4553	tolerate a **partially initialized** device — "close only what is open" — the
4554	same defensiveness the crash path already demands. **No new diagnostic kind**:
4555	`DeviceCrash`'s payload (device id, `cause`, whether `should_abort` was set)
4556	already fits an init-time failure, [Appendix C][sC]'s gloss merely naming the site. A
4557	failed device is **dead from boundary zero** with no dead-marking machinery of
4558	its own — it never stores a heartbeat timestamp, so its cell reads stale
4559	against [§12.2][s12-2]'s threshold from the first frame ([§11.8][s11-8], [D-136][d-136]) — and its **claims
4560	persist to run end**: [§11.3][s11-3]'s death-is-not-detach disposition applied one step
4561	earlier than [§12.4][s12-4](6)'s, the orphaned slots holding their initial values,
4562	well-defined by [§14.6][s14-6]'s slot totality where a (6) orphan holds a last drained
4563	batch. **Run disposition splits on `should_abort`, uniformly with (6)**: clear
4564	(the default) the remaining entries initialize, the run starts and the sim runs
4565	with the device absent from frame zero — (6)'s semantics shifted to `t₀`; set,
4566	the failure requests a control-plane stop that is **already pending at boundary
4567	zero**, so the run reuses [§13.5][s13-5]'s existing terminal-at-`t₀` path — remaining
4568	entries still initialize, every rostered device getting its `init!`/`shutdown!`
4569	pair uniformly, boundary zero is published, the run ends `stopped` at `t₀`
4570	through the ordinary [§12.4][s12-4] tail and the termination record names the source.
4571	**Topology is derived after initialization** ([§11.1][s11-1]): a failed
4572	`needs_calling_task` holder returns the loop to the calling task rather than
4573	parking it on a device that will not exist. Finally `should_abort` gets the
4574	**declaration site** it never had: an **`attach!` keyword, default `false`** —
4575	matching (6)'s narrative default ("the sim continues with the device absent"; a
4576	dead joystick must not kill a session) — with the **shipped GUI attaching
4577	`should_abort = true`** (closing the window is the interactive session's
4578	natural end) and `gui = true`'s standard attachment stating that value
4579	([Appendix B][sB], [D-134][d-134]'s sugar unchanged); [Appendix D][sD] gains the glossary entry.
4580	
4581	**Rejected.**
4582	- *Requiring `init!` to clean up after itself on failure:* an unenforced burden
4583	  duplicated in every device, and unenforceable in exactly the half-built cases
4584	  that matter — the bracket does it once, for all of them.
4585	- *Short-circuit teardown on an aborting init failure, ending the run without
4586	  publishing:* invents a second exit path beside [§12.4][s12-4]'s one tail and yields a
4587	  `stopped` sim with no terminal snapshot — unserviceable by [§14][s14], with nothing
4588	  for the log's unconditionally-retained endpoints to retain.
4589	- *A dedicated init-failure diagnostic kind:* `DeviceCrash`'s payload and
4590	  disposition already fit, and [Appendix C][sC]'s closed set pays for every addition.
4591	- *Topology frozen from the roster before initialization, the status quo:*
4592	  parks the loop on a spawned task and the calling task on a loop body for a
4593	  device that does not exist.
4594	- *`should_abort` defaulting to `true`:* a dead peripheral kills a session —
4595	  the opposite of [§12.4][s12-4](6)'s stated intent.
4596	- *Declaring `should_abort` in the device authoring contract as a fifth
4597	  function or a trait:* it is an *attachment* fact — the same device is
4598	  advisory in one deployment and relied on in another, and the contract is
4599	  the place where per-deployment policy least belongs.
4600	- *Leaving initialization failure at "reported by name through (6)'s crash
4601	  path":* the clause under review — (6) is written about a task that has
4602	  already spawned, so it answers none of release, disposition or topology.
