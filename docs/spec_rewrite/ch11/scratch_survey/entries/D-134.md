4271	### D-134 — Declare the interactive write-surface class via a binding marker method
4272	
4273	**Status.** ratified
4274	
4275	**Position.** The derived write side becomes **declared**: `interactive(b)` is
4276	an optional marker method on the *binding* — the write-surface class is a
4277	binding fact, not a device fact — probed at attach exactly like the other sides
4278	([§11.6][s11-6]'s method-presence idiom).
4279	
4280	**Spec.** [§11.2][s11-2], [§11.3][s11-3], [§11.4][s11-4], [§11.6][s11-6], [§11.7][s11-7], [§12.3][s12-3], Appendices B/C/D
4281	
4282	**Rationale.** Completes [D-044][d-044]'s partition. `interactive` defined ⇒ derived
4283	write side: no claims staked, and [§11.4][s11-4]'s positional staging shape compiled over
4284	the unclaimed face set instead (that compilation already existed; it now has
4285	its declared trigger). `interactive` and `faces` are **mutually exclusive** (a
4286	surface cannot be enumerated and derived at once — attach-time error naming
4287	both declarations); `interactive` is orthogonal to `selectors` (an interactive
4288	front end may also drive a compiled output gather — legal, currently
4289	uninstantiated, the plausible customer a narrow-wire interactive surface such
4290	as a motorized control board); "neither ⇒ error" becomes "none of the three ⇒
4291	attach-time error". **At most one interactive device per roster**, beside the
4292	always-present harness cell: a fourth part of the attach-time admission check,
4293	in `needs_calling_task`'s shape and error style (`InteractiveConflict`, naming
4294	both the rostered holder and the candidate, exactly as `CallerTaskConflict`
4295	does) — the derived surface is shared rather than partitioned, and the
4296	singleton keeps intra-surface drain order trivial (interactive device, then
4297	the harness cell last). The shipped GUI binding is the class's **sole shipped
4298	instance**, declaring `interactive` only: no `faces` (its surface is computed),
4299	no `selectors` (its read path is the handle's primitive read — VSync-paced
4300	`latest` per render, [§12.3][s12-3] — with an ad-hoc render-time read set over the whole
4301	snapshot in an inspection read's shape, [§11.2][s11-2], so the compiled gather has
4302	nothing to do for it); `gui = true` becomes "attach the standard GUI device
4303	under the standard interactive binding iff no interactive device is already
4304	rostered" ([D-109][d-109]'s idempotency, now stated against the class rather than the
4305	type). Two non-reopenings are on record: [§11.6][s11-6]'s rejected `sides(b)` trait is
4306	*not* what this marker revives — that rejection turns on redundancy with
4307	methods that must exist anyway, and nothing analogous exists here, the derived
4308	surface being computed, so no method's presence could witness the class and a
4309	marker is the only possible declaration, not a second copy of a fact; and
4310	[D-044][d-044]'s rejection of unclaimed-surface opportunism "for any device" stands
4311	unchanged — autonomous devices still enumerate, the interactive writer stays
4312	human-mediated, singleton-limited and staging-checked (`ClaimedFaceEntry`
4313	untouched). The marker makes the privileged class visible and checkable, not
4314	open.
4315	
4316	**Rejected.**
4317	- *`faces(b) = :derived` (a sentinel return):* i.e. a dual-meaning enumeration
4318	  contract — exactly the ambiguity the declaration vocabulary is built to
4319	  refuse.
4320	- *Empty-tuple-or-`nothing`-means-derived:* silent promotion of an accidentally
4321	  empty enumeration — `faces` bodies are ordinary code, comprehensions included
4322	  — to the interactive writer's *maximal* write surface: the silent-widening
4323	  class this design refuses everywhere, and the most privileged classification
4324	  must be the hardest to enter by accident; `faces(b) = ()` keeps its honest
4325	  meaning, an inert enumerated device whose writes are still binding-bounded by
4326	  `OutOfClaimEntry`.
4327	- *A shipped concrete `InteractiveBinding` type:* edges toward the abstract
4328	  binding-type taxonomy [§11.6][s11-6] already rejected, and abandons the method-presence
4329	  idiom the other sides use.
4330	- *Forbidding `interactive` + `selectors`:* orthogonal machinery, and a rule
4331	  that would have to be unmade for the first narrow-wire interactive surface.
4332	- *Leaving the class undeclared with the GUI special-cased:* the status quo
4333	  under review — [§11.3][s11-3]'s "the GUI is not an exception but the resident of the
4334	  second class" stays aspirational, the class has no membership test, and a
4335	  second interactive front end has no spelling.
