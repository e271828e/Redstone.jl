8124	### D-218 — Make the replay/live distinction an explicit input mode
8125	
8126	**Status.** ratified
8127	
8128	**Position.** A `Simulation` carries an input mode, `:live` or `:replay`, read
8129	as `mode(sim)` beside its lifecycle state, and the one drain branch ([D-101][d-101]'s
8130	second substitution) is driven by that mode.
8131	
8132	- `replay!` attaches the recording and enters `:replay`. `step!` and `run!`
8133	  consume it frame by frame from there, live staging taken and discarded
8134	  (`ReplayDiscardedStaging`), devices running as readers.
8135	- While the mode is `:replay` the recording is the bound: every advance's
8136	  frame budget is capped at the recording's last frame, `to_boundary` capping
8137	  it earlier, and the halt leaves the simulation `initialized`.
8138	- The mode becomes `:live` exactly when a halt lands at the recording's end,
8139	  the records exhausted, and stays `:replay` otherwise. `init!` and a fresh
8140	  `replay!` reset it with the trajectory.
8141	
8142	**Spec.** [§12.6][s12-6], [§12.7][s12-7], [§13.4][s13-4]
8143	
8144	**Rationale.** [§13.4][s13-4] promises that after `replay!(sim2, trc; to_boundary = k)`
8145	a `step!` re-executes frame k+1 on its recorded inputs. The promise needs the
8146	recording to still have a consumer after `replay!` returns, which a mode
8147	outliving the call supplies. [D-101][d-101]'s shape is untouched — one loop, one drain
8148	branch, replay as the ordinary loop with two substitutions — and only what
8149	selects the branch's source moves, from the incidental presence of a feed to a
8150	register the caller can read. The recording as the bound is what keeps the
8151	distinction honest across a halt: an advance never leaves the records behind
8152	and keeps going, so every frame of a session is either record-driven or live,
8153	and which one it was is readable before it runs.
8154	
8155	**Rejected.**
8156	- *The implicit switch — a feed present only while the replay call runs:* the
8157	  feed is dismantled when the replay loop exits, so after a partial replay the
8158	  record at ordinal k+1 has no consumer and the following `step!` runs a live
8159	  frame with empty staging. [§13.4][s13-4]'s reproduction workflow then reproduces a
8160	  different frame, silently.
8161	- *Re-staging the halt-adjacent records into the live staging cells:* it needs
8162	  a write path that bypasses the write-surface rule ([§11.3][s11-3]), recorded batches
8163	  applying with no surface re-check, and it covers one frame only — the next
8164	  advance is live again.
8165	- *A silent mid-run flip to `:live` when the recording runs out:* one `run!`
8166	  would change input source mid-call, and nothing the caller reads afterwards
8167	  would say where the reproduction stopped reproducing.
