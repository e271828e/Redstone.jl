4337	### D-135 — Scope the activation cache to immutable compiled artifacts, keyed on the Build
4338	
4339	**Status.** ratified
4340	
4341	**Position.** Amending [D-052][d-052], the activation cache is scoped to **immutable
4342	compiled artifacts** — layouts, compiled plans, the validated flag — keyed by
4343	concrete scalar type and living on the **`Build`**, since an activation is a
4344	pure function of the build and the scalar ([§9.4][s9-4]'s own words).
4345	
4346	**Spec.** [§9.8][s9-8], [§11.1][s11-1], [§9.2][s9-2], [§9.4][s9-4], [§14.8][s14-8]
4347	
4348	**Rationale.** **Every buffer set has exactly one owner**: the `Simulation`
4349	owns its nominal activation's buffers, materialized from the cached layouts at
4350	construction and what the loop's zero-allocation stepping runs on; every
4351	service invocation owns the scratch set it instantiates from those same layouts
4352	— [§14.8][s14-8]'s per-invocation rule promoted from a trim-local statement to the
4353	general one, [D-070][d-070] being the decision that forced it (iterating on shared
4354	buffers aliases the sim's authoritative stores, warn-but-assign reborn). The
4355	envelope-grid sweep's amortization is restated honestly: what the cache saves
4356	is probe re-runs, layout construction and Julia's compilation of the `Dual`
4357	chain — never buffer reuse, the per-point working-store allocation being
4358	O(model size) and trivial against the solve it feeds, and [§9.8][s9-8]'s
4359	zero-allocation invariant being scoped to the stepping loop (the services were
4360	always allocation-tolerant, [§14.8][s14-8]). Two consequences stated where they belong:
4361	the `Build` is an **immutable artifact that may back any number of
4362	`Simulation`s, concurrently** ([§9.2][s9-2] — true by construction once buffers are
4363	single-owner, which is what [§9.2][s9-2]'s `Simulation(build::Build; …)` factorization
4364	plus [§11.1][s11-1]'s inline-`run!` parallel sweeps were already inviting), and **lazy
4365	materialization is torn-state-free under concurrent first requests** as a
4366	normative guarantee, mechanism unspecified (a guard around insertion suffices,
4367	at service time and never on the hot path; purity makes the worst benign race
4368	duplicated work). Recommended idiom for [§11.1][s11-1]'s parallel sweeps,
4369	recorded at both sites: pre-materialize with the existing `build(world;
4370	activations = …)` keyword and the shared artifact is fully immutable, with no
4371	synchronization on any path.
4372	
4373	**Rejected.**
4374	- *Cached shared buffers:* [D-070][d-070]'s aliasing — warn-but-assign reborn — and it
4375	  makes the `Build` mutable in exactly the way multi-`Simulation` sharing
4376	  forbids.
4377	- *Per-`Simulation` activation caches:* defeats the sharing [§9.2][s9-2]'s artifact
4378	  factorization bought: every worker re-probes and re-compiles.
4379	- *Requiring explicit pre-materialization for any concurrent use:* turns a
4380	  safety property into a user obligation — the guard is cheap and off the hot
4381	  path, and a sweep that forgets the keyword would get corruption rather than a
4382	  slower first request.
