2698	### D-087 — Freeze the device roster as a build-validated immutable value
2699	
2700	**Status.** ratified
2701	
2702	**Position.** Device roster representation and trace tags ([§11.3][s11-3]), as narrowed
2703	by the [D-106][d-106] freeze: the roster (entries, claims, order) is a plain immutable
2704	value the loop reads once at `run!` — no republication, no per-frame
2705	acquire-load, no sequence numbers (attachment order = the roster's own order).
2706	
2707	**Spec.** [§11.3][s11-3]
2708	
2709	**Rationale.** The roster post-dates the build and `attach!` validates against
2710	the `Build` artifact; trace device tags are stable ids, never roster indices —
2711	ids read across runs, where the roster does change.
2712	
2713	**Rejected.**
2714	- *Superseded position — attach/detach legal at any time, an atomically
2715	  republished roster acquire-loaded per frame top with mid-frame attach taking
2716	  effect next frame, sequence numbers for order stability, claim release on
2717	  detach and on the `should_close` exit path (earlier design of record):*
2718	  superseded wholesale by the [D-106][d-106] roster freeze.
2719	- *Roster fixed at build:* devices post-date the build.
2720	- *Roster-index trace tags:* indices unstable *across runs* — the replay's
2721	  trace tag broken.
2722	- *Mid-run claim release on task death:* the freeze adopts the reverse: see
2723	  [D-106][d-106]'s reversal note.
