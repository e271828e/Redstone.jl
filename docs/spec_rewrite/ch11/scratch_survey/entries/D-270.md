11153	### D-270 — Fix the framework's half of the panel convention: port views, the peek, the orphan fact
11154	
11155	**Status.** ratified
11156	
11157	**Position.** [§11.7][s11-7]'s panel-authoring convention splits into a framework
11158	half, fixed now and independent of any GUI library, and a GUI-package half
11159	that stays deferred. A panel reads the framework through three values, a
11160	port view, the device handle and a snapshot, and nothing else.
11161	
11162	- `port_views(handle)` bakes one `PortView` per declared port of every
11163	  component, input and output, keyed by `(path, port)`: the terminal
11164	  producer, the liveness verdict, the staging slot when live, the producer's
11165	  cell address and the incumbent writer of a root-driven port the GUI does
11166	  not command. The GUI's loop body builds it once at its top, after the
11167	  freeze. The handle carries the build's `Structure` and the nominal
11168	  `Layout` by reference for it.
11169	- `pending(handle, slot)` reads the handle's own staging cell with one
11170	  acquire load and never takes it, `Some(value)` when the slot is touched
11171	  and `nothing` otherwise. `peek_port(view, handle, snapshot)` is [§11.7][s11-7]'s
11172	  peek rule composed over that read and the snapshot.
11173	- `incumbent_status(view, snapshot)` returns the incumbent's `WriterStatus`
11174	  from the snapshot's status, or `nothing` for a port no device writes.
11175	  `orphaned(record)` is a `:done` or `:failed` task; `stale` is unchanged.
11176	- The window between the frame-top drain and that frame's publication, in
11177	  which a live widget shows the previous snapshot's value, is recorded as
11178	  the rule's own consequence, harmless under the levels doctrine.
11179	- `PortView` holds its cell address in an abstract field, and the table is
11180	  a `Dict`.
11181	
11182	**Spec.** [§11.7][s11-7], [Appendix B][sB]
11183	
11184	**Rationale.** The deferred convention had two owners hiding in one
11185	sentence. What the drawing context carries and how widgets are drawn
11186	depends on the library, and the GUI package (separate, never a dependency
11187	of the core) decides it. What a widget *knows* about its port does not
11188	depend on the library at all: the wiring is the build's, the claim
11189	partition is frozen at `run!`, the staging cell and the snapshot are the
11190	core's. Fixing that half now retires the `pending.md` bullet against a
11191	concrete API and hands the GUI package fixed inputs.
11192	
11193	Three pieces are new, and each is a read of state the core already holds.
11194	The port view assembles `ComponentEntry.conns` (the terminal producer,
11195	walked across every level at build), `writer.faces` (the claim, whose
11196	position is the staging slot), the exclusivity index and `layout.addr`.
11197	Baking at the loop's top rather than at `attach!` is what keeps the
11198	incumbents honest: a handle's own claim never changes after its attach, but
11199	the incumbent of a face another device claims later does, and reading the
11200	index at render is what [§11.7][s11-7] forbids. The bake is plain runtime data, a few
11201	hundred `Dict` operations once per run, and no new compilation: the one
11202	`@generated` reader on the path, `gather_cell`, is already specialized for
11203	every address in the model.
11204	
11205	The peek pays for itself in three places. While paused there is no frame
11206	top and so no drain, and a snapshot-only widget shows the pre-pause value
11207	whatever the user stages, so paused editing is blind; the same holds for a
11208	hand-attached GUI staging before `run!`. An edge widget computing "current
11209	plus one" from the snapshot loses every click after the first inside one
11210	drain window, which is every click while paused. And an immediate-mode
11211	slider passed the snapshot value while dragged jumps back each pass until
11212	the drain catches up. The peek reads the one place the design already keeps
11213	"what I staged that has not applied", so it adds no state; widget-local
11214	shadow copies would add one per widget, disagree across fan-out and need
11215	their own invalidation on drain.
11216	
11217	The orphan fact needs no new channel. The writer record in the snapshot's
11218	status carries `task_state` off the run's task registry and the heartbeat
11219	off the handle primitives, so a widget joins its view's incumbent to that
11220	record by name. Dead and stale are different axes: dead is a fact that
11221	will not change this run, stale is a silence that may clear, and the record
11222	distinguishes an exited loop from a crashed one. Only the dead case is on
11223	the widget label by rule; the GUI package may show the silence and its
11224	age beside it, since the record is in hand.
11225	
11226	The abstract address field costs one dynamic dispatch per widget per render
11227	pass, tens of microseconds per second over a cockpit, and a parametric
11228	`PortView` would still sit in a `Dict` typed on the abstract type. Output
11229	ports join the table so a generated panel is one loop over the component's
11230	faces with no branch on kind; they roughly double a table of a few hundred
11231	entries.
11232	
11233	**Rejected.**
11234	- *A snapshot-only widget, no peek:* blind while paused and before `run!`,
11235	  lost clicks on edge widgets inside a drain window, and a slider that
11236	  fights the hand under immediate-mode rendering.
11237	- *Widget-local shadow state in place of the peek:* a second copy of the
11238	  staging cell's content per widget, inconsistent across fan-out and in
11239	  need of its own invalidation on drain.
11240	- *Baking the views at `attach!`:* correct for the handle's own claim and
11241	  slots, stale for the incumbent of a face claimed by a later attach, and
11242	  repairing that at render means consulting the index at render.
11243	- *A parametric `PortView{A<:CellAddr}`:* buys a specialized `peek_port`
11244	  only where a panel captures views into concretely typed fields, on a
11245	  render path where the dispatch is noise.
11246	- *A framework-owned drawing context:* what the context bundles beyond the
11247	  three values is the library's question, and the core would be guessing
11248	  at a widget model it does not ship.
11249	- *`peek` as the API spelling:* `Base.peek` exists for streams and
11250	  iterators; the naming rule appends the target where the spec's verb is
11251	  the right verb, hence `peek_port`.
11252	
11253	Annotation (2026-09-28): two rulings the cold review raised. The input
11254	views come off `Structure.in_faces`, not off each primitive's `conns`, so
11255	an assembly's input faces and the root's own get views; a root input's view
11256	has itself as source, which is the cockpit widget that commands it
11257	directly. And `:failed` is unreachable for a device task, the wrapper
11258	catching every non-interrupt throw, while two dead writers read alive
11259	under the letter above: a device whose `init!` threw has no task and read
11260	`:none`, and a calling-task device whose inline body returned read
11261	`:running` off `run!`'s own task. [§12.2][s12-2] now rules `task_state` as `:none`
11262	outside a run and, inside one, `:done` for any device without a live task
11263	of its own, so `orphaned` is exactly `:done` and the crash count tells a
11264	crash from a return.
11265	
11266	Annotation (2026-10-05): `peek_port` is renamed `peek`, the spec's own
11267	verb, and the rejection above is reversed in part. The clash with
11268	`Base.peek` is a concern for an exported name, where a bare `peek` in a
11269	user's module becomes ambiguous or silently stays Base's. The panel kit is
11270	extension-only surface, reached by qualified name or explicit import like
11271	the device contract, and a name imported that way coexists with Base's
11272	qualified spelling. The module exports nothing until the audit ([D-226][d-226]),
11273	which records the coincidence as a boundary case (`pending.md`). The GUI
11274	package's context verb is a method of the same function, `peek(ctx, face)`
11275	beside `peek(view, handle, snapshot)`, so one verb keeps one meaning across
11276	the two halves. [§11.7][s11-7] and [Appendix B][sB] carry the new spelling; this entry
11277	keeps its own.
11278	
11279	Annotation (2026-10-07): the input views come off `terminal_producer` over
11280	every input face at every level, `Structure.in_faces` having gone with [D-315][d-315].
11281	The rulings stand.
