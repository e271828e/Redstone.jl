3260	### D-106 — Freeze the device roster for the duration of a run
3261	
3262	**Status.** ratified
3263	
3264	**Position.** Roster freeze: `attach!`/`detach!` are stopped-sim operations —
3265	legal in `built`/`initialized`/`stopped`, an error while `running`, pause
3266	included (pause is inside a run) — so the roster and the partition of the root
3267	face set into per-writer surfaces plus the interactive remainder are static,
3268	inspectable facts of each run; attach has one semantics (register; tasks appear
3269	at `run!`, [D-093][d-093]).
3270	
3271	**Spec.** [§11.3][s11-3], [§12.3][s12-3], [§12.5][s12-5], [§12.7][s12-7]
3272	
3273	**Rationale.** All write-surface checks move to staging and the drain is pure
3274	application, fully compilable against the frozen roster (specialization an
3275	implementation freedom, not an obligation — the [§9.7][s9-7] per-configuration compile
3276	trade); device death mid-run is not detach — the task dies, the heartbeat
3277	reports it, claims and roster entry persist to run end (**reversal of [D-087][d-087]'s
3278	zombie-claims rejection**: that rejection served dynamic liveness derivation,
3279	and with liveness baked per run the rationale inverts — a mid-run release would
3280	move a surface nothing can soundly recompute); orphan recovery is between runs
3281	(stop → `detach!` → `init!`, or `replay!`-to-end + `run!` continuation, [§12.7][s12-7]);
3282	[§12.5][s12-5]'s doctrine reaches final form — the running periphery stages writes and
3283	issues control commands, and nothing else changes. **Guarded addition on
3284	record**: mid-run attach for pure readers (no input half — claims nothing,
3285	moves no surface; a dynamic reader list touches only [§12.3][s12-3] wakeups, heartbeat
3286	and shutdown join, never the drain), cleanly severable should
3287	join-a-running-session find a customer. Supporting fact: FlightCore has no
3288	mid-run attach — every demo attaches before `run!`, and `run!` blocks its
3289	caller in both designs, so the dropped capability had no demonstrated customer
3290	and was barely reachable.
3291	
3292	**Rejected.**
3293	- *The earlier attach-anytime design of record:* [D-087][d-087]'s republished-roster
3294	  machinery, drain-time derived-surface membership checking via
3295	  `StaleInteractiveEntry`, [§11.7][s11-7]'s mid-drag claim-transition policy, per-attach
3296	  thread-budget re-checks — all priced for a hypothetical workflow.
3297	- *Mid-run claim release on device death:* the reversed [D-087][d-087] rejection — under
3298	  a frozen surface it is the *release* that would be unsound.
3299	- *Attach-while-paused:* a surface change inside a run — forfeits every
3300	  staticity benefit at the moment it is exercised.
3301	- *Reader exception adopted now rather than guarded:* no customer; the freeze
3302	  stays maximally simple.
