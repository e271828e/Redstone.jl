2951	### D-096 — Define the harness writer: `stage!`/`latest`/`step!` duration
2952	
2953	**Status.** ratified
2954	
2955	**Position.** The harness writer ([§12.6][s12-6], [§11.3][s11-3], [§11.2][s11-2]): `stage!(sim, "face" =>
2956	value, ...)` = task-free staging from the calling task into the interactive
2957	writer ([D-044][d-044]'s derived surface) — traced, surface-checked, drained *last* at
2958	the frame top (the explicit hand of code beats a widget interaction; sequencing
2959	within one writer, not cross-device policy), so the mutation doctrine
2960	(staging and control, nothing else) and replay bit-identity hold.
2961	
2962	**Spec.** [§11.2][s11-2], [§11.3][s11-3], [§12.6][s12-6]
2963	
2964	**Rationale.** `latest(sim)` = the current published snapshot, the same
2965	immutable value device handles read; `step!` gains the duration spelling
2966	`t_plus` (whole frames until the boundary time covers the duration, mutually
2967	exclusive with `frames`); together the write/read halves of [D-088][d-088]'s
2968	advance-assert and fly-inspect idioms and the migration path for the suite's
2969	dominant write-`u` → `step!` → assert idiom.
2970	
2971	**Rejected.**
2972	- *A special harness device:* a device with no task is `stage!` with extra
2973	  ceremony.
2974	- *`step!(sim; inputs = …)` drain-from-argument:* a second staging spelling
2975	  with no `run!` analogue.
2976	- *Direct slot pokes from the calling task:* [§2.5][s2-5]/[§12.5][s12-5]'s rejected
2977	  unrecorded-mutation idiom — breaks replay.
2978	- *Leaving reads to device handles or the log:* the log can be off, a handle
2979	  needs a device, and [D-088][d-088]'s "inspect" must be spellable.
2980	- *A public closure-evaluation API:* [§13.5][s13-5]'s rejected cost — an inspection
2981	  *accessor* returning the immutable snapshot is not it.
