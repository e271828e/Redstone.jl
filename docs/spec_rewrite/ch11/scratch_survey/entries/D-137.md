4458	### D-137 — Bound snapshot-log retention by count, with amortized doubling stride
4459	
4460	**Status.** ratified
4461	
4462	**Position.** Snapshot-log retention gets a **bound**, `log_max` — the maximum
4463	number of retained snapshot references, a new `Simulation` keyword beside
4464	`log`/`log_every`.
4465	
4466	**Spec.** [§4.1][s4-1], [§4.4][s4-4], [§9.8][s9-8], [§10.7][s10-7], [§11.2][s11-2], [§11.5][s11-5], [§11.8][s11-8], [§12.4][s12-4], [§12.7][s12-7], [§13.5][s13-5],
4467	Appendices B/D
4468	
4469	**Rationale.** **A count, not a memory budget**: snapshots are immutable object
4470	graphs with internal sharing ([§4.1][s4-1], and [§4.4][s4-4] field handles riding as references
4471	to build-time-frozen data, [§9.8][s9-8]), so byte accounting over them is fuzzy and
4472	platform-dependent, while a count is exact and converts to memory through one
4473	number the user measures once (`Base.summarysize` of a single snapshot).
4474	**Default 65536 (2¹⁶), finite unconditionally**, with `Inf` the explicit
4475	opt-out — no modal rule keyed on `t_end`; a finite run shorter than the bound
4476	never notices it, and at 50 Hz full density 2¹⁶ boundaries is ≈22 minutes
4477	before the first drop. **When the log fills, the effective retention stride
4478	doubles** — `log_every · 2^k` after k generations — so the bound holds while
4479	coverage stays **global**: the whole run remains plottable at coarsening
4480	density, which is [D-038][d-038]'s division of labor carried through (the log's chief
4481	consumer is the post-run plot of a session as a whole; full density over any
4482	*segment* of interest is what replay from the trace recovers, [§11.5][s11-5], [§12.7][s12-7]). The
4483	licence is [D-038][d-038]'s own asymmetry, a fortiori: a thinned log costs resolution in
4484	a *view*, never a record, whereas [D-029][d-029]'s refusal to thin the trace stands
4485	untouched. Following [D-135][d-135]'s precedent, **the guarantees are normative and the
4486	mechanism a sketch**: normatively the retained count never exceeds `log_max`,
4487	coverage is global at the effective stride, and the endpoints are kept; the
4488	sketch is that the thinning is **amortized** — the stride doubles immediately
4489	and each subsequent retained append also releases one predecessor of the
4490	previous generation (a cursor over the odd indices, O(1) amortized, physical
4491	compaction once per generation), the generation's thinning completing exactly
4492	when its refill does. Amortization is a responsiveness choice: a one-shot
4493	halving would make ~`log_max/2` *old-generation* snapshots unreachable at a
4494	stroke, a major-GC burst worth a pacer-absorbed, `DebtReanchor`-visible hiccup
4495	([§10.7][s10-7]) — exponentially rare, the wall-clock gap between generations doubling,
4496	but needless — while the amortized form drops exactly one old snapshot per
4497	retained append, the steady trickle a rolling window would produce anyway; the
4498	loop's own work is pointer bookkeeping, microseconds either way and on the
4499	framework side of [§9.8][s9-8]'s scope, publication staying wait-free with readers
4500	never blocking. **The boundary-zero ([§14.5][s14-5]) and terminal ([§12.4][s12-4](1), [§13.5][s13-5])
4501	snapshots are retained unconditionally under any `log_every` and any `log_max`,
4502	and do not count against the bound** — two extra references — so the run's
4503	endpoints and, via the terminal status's final cumulative counters ([§11.8][s11-8],
4504	[D-136][d-136]), its complete diagnostic account always survive. Compositions stated
4505	once: `totals` monotonicity across logged snapshots ([§11.8][s11-8]) is unaffected,
4506	re-decimation losing *which* boundary in a stretch an occurrence fell on and
4507	never *how many*; and `log_max` is a **view policy, not
4508	trajectory-determining** — outside the trace header's deployment block, neither
4509	recorded nor compared by replay ([D-127][d-127], [D-133][d-133]'s compared set untouched). [§9.8][s9-8]'s
4510	`sizehint!` for the expected duration is reconciled: now capped by `log_max`,
4511	which is also what defines the hint when `t_end = Inf`. No new diagnostic kind
4512	— hitting the bound is stated policy, not an event to report.
4513	
4514	**Rejected.**
4515	- *A rolling window:* optimizes recent-past-at-full-density, which replay
4516	  already serves, at the cost of the whole-run overview replay is expensive for
4517	  — and it buys no responsiveness either, its steady-state drop rate being
4518	  exactly the amortized form's.
4519	- *A memory-based bound in bytes:* false precision over shared immutable graphs
4520	  — the number would be platform-dependent and unauditable, where a count is
4521	  exact and one measurement converts it.
4522	- *A modal default, finite only when `t_end = Inf`:* a modal rule where one
4523	  unconditional number suffices, and the finite-`t_end` run it exempts is the
4524	  one that never reaches the bound anyway.
4525	- *An unbounded default, the status quo under review:* gigabytes per hour at
4526	  C172X scale and 50 Hz in the configuration [Appendix B][sB] calls the honest
4527	  interactive default, ending in an OOM no diagnostic mentions.
4528	- *One-shot halving as the normative mechanism:* an old-generation major-GC
4529	  burst once per generation — pacer-absorbed and rare, but needless when
4530	  amortization achieves the rolling window's trickle profile at the same
4531	  asymptotic cost.
4532	- *A diagnostic kind for reaching the bound:* a policy operating exactly as
4533	  configured is not a warning, and the log's density is visible in the log
4534	  itself.
