3234	### D-105 — Split device-side bad-datum handling into tolerated garbage and propagated crashes
3235	
3236	**Status.** ratified
3237	
3238	**Position.** Device-side bad-datum policy: two failure classes, two fates —
3239	environmental garbage (truncated datagram, malformed JSON, out-of-range field)
3240	is tolerated in the loop body (catch, stage nothing, `report(handle,
3241	MalformedDatum(cause))`, continue; rate-limited per device — the `maxlog = 25`
3242	successor), any other exception propagates to the wrapper as `DeviceCrash`.
3243	
3244	**Spec.** [§11.6][s11-6], [§13.2][s13-2], [§13.4][s13-4]
3245	
3246	**Rationale.** Classification is the author's, as FlightCore's
3247	`InputMappingError` docstring already assigned it; `report(handle, …)` is
3248	scoped to device-attributed runtime warnings, not a general user-diagnostics
3249	channel; companion drain-family kind `EntryTypeMismatch` for values
3250	unconvertible to the slot's declared type, checked at staging for every writer.
3251	
3252	**Rejected.**
3253	- *A marked exception type (`InputMappingError` successor):* vestigial under
3254	  the author-owned loop, since no framework per-iteration catch site exists to
3255	  consume it.
3256	- *Spec silence:* the natural reading reproduces first-bad-packet-kills-device,
3257	  for the whole run under [D-093][d-093].
3258	- *Tolerate-everything:* hides bugs as "device attached, nothing happens".
