9149	### D-241 — Keep the status a vector of records, one small allocation per publication
9150	
9151	**Status.** ratified
9152	
9153	**Position.** The published framework status is a `Vector` of per-writer
9154	records built at each publication, one small allocation beside the
9155	snapshot's own. The snapshot type is fixed per model and does not vary with
9156	the roster size.
9157	
9158	**Spec.** [§11.8][s11-8]
9159	
9160	**Rationale.** [§11.8][s11-8] read "zero additional heap allocation on a quiet
9161	frame", and the implementation honoured it literally for one commit: a
9162	status tuple sized to the roster, a snapshot type carrying it, and a
9163	publication bound per roster change behind a barrier on the writer count,
9164	since an immutable `Simulation` crossing a dynamic call is boxed. Measured,
9165	the tuple saved two allocations of a few hundred bytes next to the
9166	snapshot's store copy. It cost 30 ns of dispatch per publication and about
9167	120 ms of compilation per roster size per process, every consumer of the
9168	snapshot type recompiling with it. The periphery's doctrine is [D-023][d-023]'s
9169	GC-over-reuse trade: one fresh allocation per boundary rather than buffer
9170	management. A second small allocation beside an accepted one changes
9171	nothing the collector feels; a snapshot type per roster size changes what
9172	every attach costs. The decisive invariant is the one the vector keeps:
9173	nothing on a quiet frame scales with diagnostic activity, the counters are
9174	an isbits record, and a noisy frame allocates only its rings.
9175	
9176	**Rejected.**
9177	- *A status tuple sized to the roster, in the snapshot's type:* two fewer
9178	  small allocations, bought with a compile per roster size per process and a
9179	  publisher rebound at every roster change; the zero-additional sentence was
9180	  [§9.8][s9-8]'s invariant extended past the scope [§9.8][s9-8] gives it.
9181	- *A fixed-capacity tuple:* no compile per size, but a cap on the roster and
9182	  a record's worth of bytes per unused slot in every snapshot.
