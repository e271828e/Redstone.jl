Glossary

This is the vocabulary the reference uses, generated from the design's glossary.

Component model and declaration layer

abstract entry — an u_types entry whose declared type is abstract. It states structural substitutability: any concrete producer face below the bound wires to it. The field handles are the demonstrated client. It is never needed for eltype genericity, and it is illegal where the face surfaces as a root input (AbstractAtRoot).

assembly — a component that holds child components and wires them together. It has no dynamics of its own. Its component-typed fields are its children, and it declares local_wires (mandatory, the class marker), input_wires, output_wires, sample_times and the optional transparent_container. It is flattened away for ordering, and retained as the navigation hierarchy and as declaration-level rate scopes.

auto-bubbling — promoting an unconnected input automatically to a root input. The framework never does it, and an unconnected input port is a build error. Deriving a passthrough's except from the assembly's own wire list would be auto-bubbling under another name.

block — a component the standard library ships. The word carries no framework meaning, and a block has no privilege a user's component lacks.

bound law / walk clause — the two clauses that type-check a wire. The bound law requires the producer's declared type at nominal to be a subtype of the consumer's input entry, and equal to it for a concrete entry. The walk clause, for a continuous consumer only, requires an unpinned entry for a walking producer leaf.

branch-shape rule — a stage's return must have the same NamedTuple shape on every branch. It bans return types that depend on input values. A port missing from an untaken branch fails at that branch's first execution, under the always-on check.

class — a component's primitive-vs-assembly status, read off which well-known declarations its type defines. local_wires makes an assembly, any of the primitive declarations makes a primitive, and neither is ClassUnreadable. Class is neither a tier nor a diagnostic kind. The phrase "two leaf classes" names the tiers in ordinary English.

component — the unit of modeling. It is a primitive or an assembly of components.

container children — a Tuple/NamedTuple field whose elements are all components. It contributes them as children path-named "field/1" or "field/key", or by bare key ("1" or "key") where the field is declared name-transparent via transparent_container. It is transparent grouping, not an assembly: no contract, no local_wires, no rate scope.

continuous component — the hybrid primitive. Its facets are continuous state x, modes m, the flow x_deriv, two output stages, events (guards with handlers) and an optional x_projection. Any facet may be empty. One with modes and events but no x is a finite-state machine.

contract — a component's declared interface. u_types states its requirements, what each entry allows to arrive. y_types states its public ports, what each cell carries. A name returned in y and declared nowhere is a build error. The derived contract and the spec's other contracts, such as the device authoring contract, are distinct senses.

declaration inventory — the closed set of well-known functions a component or assembly defines, each declared in a stated source of authority, by value, by type or by allocation. The set is the per-name import list a component's module writes. It holds x_init/s_init/m_init, ws_init, u_types/y_types, state_events, the stages, x_deriv/s_update/x_projection, local_wires/input_wires/output_wires/sample_times/transparent_container, and stop_reason.

derived contract — the checkable surface an assembly or the Build derives from declarations and wiring instead of declaring it. An assembly's is its face list. The Build's is its wire list, root inputs, execution order and face table. Under generic holding it is the constraint the referencing wires impose on the child.

export chain — the faces under which the assemblies above a port surface it, one level at a time. It is the only marking of which ports the GUI may command. Condition resolution walks it to the root input and errors if the face never surfaces. get_face and mounting resolve through it too.

function family — which bundle fields a given function may legally receive. The families are y_state/y_direct/x_deriv/s_update/guard/handler/x_projection, one closed set per name per tier, the shared output stages taking one set on each. The comment block states each family's maximal legal set, and BundleFieldError classifies a read as illegal for the family. Not a diagnostic kind.

generic holding — a parent holding a child through a non-concrete field type. The child is opaque below its faces, and the local wires and interface connections referencing those faces are the imposed derived contract, checked per instantiation.

hybrid causal system — what the framework simulates. It combines continuous flow with algebraic outputs, multi-rate periodic discrete dynamics, state events under two detection policies, post-step manifold projection and externally injected inputs.

the letters — the formulas' mathematical symbols, against the API's words. f is x_deriv, g is s_update, and h, the output map, is y_state in y = h(x) and y_direct in y = h(x, u). The bundle letters are API names. h also names the integration step. z appears only in the delay z⁻¹.

local wire — an entry of local_wires, a wire from one child's face to another's, with both ends inside the assembly's boundary. An input wire or an output wire has one end on the boundary instead.

locality law / one-level rule — the one-level rule says every connection endpoint names an immediate child and one of its faces. Routing across levels is therefore declared level by level, each assembly speaking only of its own children. That is the locality law. Condition fragments follow it as unchecked guidance.

periodic discrete component — a primitive with state s, update s_update at a declared rate, and two output stages whose cells hold zero-order between ticks. It has no m store, and its s reaches others only through signals.

primitive — a component with dynamics of its own and no children: a continuous component or a periodic discrete component, one per tier. It makes the primitive declarations, x_init or s_init among them, and its faces are its own ports.

rate scope — an assembly's sample_times declaration, mapping an immediate child name to a Relative or Absolute declaration against the enclosing scope. Relative entries compose affinely down the tree, and absolute entries anchor. All are compiled to one (D, Φ) pair per discrete component.

schema authority — the principle that declarations define structure and evaluation only checks conformance against them, never the reverse. Types come by declaration, values by execution, conformance by comparison.

stage function / two-stage outputs — every primitive provides exactly two output stages, y_state (no u in the bundle, hence structurally no feedthrough) and y_direct. One pair of names serves both tiers, and each name's legal bundle set is tier-dependent. Feedthrough is thereby declared by signature, with no dependency annotations anywhere.

state declaration — a primitive's x_init or s_init, declaring its continuous or discrete state by initial value. Every primitive makes exactly one, empty when stateless, and it marks the primitive's tier. A non-empty one owes its update law, x_deriv or s_update, and it seeds the primitive's x or s store.

workspace — component-declared mutable scratch, declared by allocation (ws_init(::C, ::Type{T}) on both tiers, a discrete allocator always called at Float64), arriving as the ws bundle field. It is excluded from state semantics, never a condition target, and never inspected or mutated by the framework. Its contents at call entry are unspecified.

Signals and data homes

buffer — the framework-owned contiguous Vector{T} backing all continuous state, laid out at build time, and the ẋ vectors the integrator fills. A component's x store is its range of the x buffer. The buffer is authoritative, and typed state values are ephemeral reconstructions of it. The integration intermediates live in framework-owned integrator buffers, never in a component's workspace.

bundle — the single NamedTuple of zero-copy views a component function receives beside the component itself. Under the bundle law a name is present iff the corresponding store or fact exists for that component. Undeclared stores are absent, never nothing-filled.

cell — one concretely typed entry of the signal table, one per output port of the flattened model, written by its producing stage and read by every gatherer. Every cell is public, and private intermediates are never cells. Bare "cell" means only this. See staging cell and store.

constant source — an ordinary library component with no inputs and no state, publishing a value its instance holds (Constant{V}). It is the spelling for an aggregate input with zero contributors and for the rig stub feeding an abstract face. Its value is instance data, never a default.

entry — a word whose sense comes from its compound, each a different thing. The compounds are table entry, a cell; input entry; wiring entry, an entry of local_wires, input_wires or output_wires; sample_times entry; executor entry; roster entry and batch entry; and condition entry.

face — the name a port wears on its component's boundary. For a primitive it is the port's own name. For an assembly it is a name declared in input_wires or output_wires, aliasing an interior port. Face names are opaque tokens, and the periphery's write side speaks only face names.

feedthrough — an instantaneous input→output dependence. Structural feedthrough is this design's version. It is fixed by which stage produces a port rather than annotated, and every stage-2 output is conservatively presumed dependent on every wired input.

field handle / function-valued signal — an immutable query object carried on an ordinary port (ISAField, TerrainField) that consumers evaluate at arguments of their own choosing. Bulk data rides as build-time-frozen references, never as mutable caches.

immutable value semantics — the signal rule, stated precisely as immutability plus frozen references (isbits is the common case, not the rule). It gives no aliasing, safe concurrent reads, and a definite per-cell freshness tied to the producer's position in the execution order.

one home per datum — the buffer holds x, the s and m stores hold s and m, and the table holds produced signals. No store mirrors another, and the table never holds transported data.

opaque leaf — an immutable type that is not isbits, where the leaf walk stops and treats it as one leaf. The table stores it whole, references included. A field handle and a Symbol are opaque leaves. An opaque leaf may not surface as a root input.

port — the addressable unit of the model: one declared name, one cell, one root input, one staged write, one device claim, one trace address, one GUI liveness verdict. Wiring is port-granular, and which stage computes a port is invisible outside the component.

root input — the root component's own input face, which is an assembly's input_wires key or a primitive's u_types key. It is produced by no component, constant within a frame, and the only thing the periphery may write.

scratch — mutable working storage whose contents are never authoritative. There are three kinds. One is a component's workspace, ws. Another is the integrator's buffers and the mid-step table. The third is the store set a service invocation instantiates from the activation's layout and discards with the call. The simulation's own buffer set is the authoritative one.

signal table — the framework-owned collection of cells holding every produced signal of the flattened model. Consumers gather views from it. Its consistency is a boundary property, and within a step it is transiently integrator scratch.

staging cell — the per-device atomic holding place where a device's pending write batch waits between drains. It is mutated frame by frame, hence outside the table's publish-once discipline. Not a table cell.

store — the framework-owned home of one of a component's state letters, x, s or m. An x store is a range of the buffer. An s or m store is a typed value of isbits or Symbol fields. The framework overwrites it when a handler or update returns a new value. A store is never a cell.

summing junction — an ordinary library component performing N-to-1 aggregation through explicit wires. It is SumJunction{V, N}, the generic Junction at +, or a named site-specific variant. There is no framework aggregation mechanism, and fold order is the junction's positional input order.

value-level constructor — the plain public function from (component, input values) to field handle that every field-emitting component is obliged to provide. Its own swept output stage is a one-line call to it. It is the device by which condition math queries the environment before any sweep exists.

view — any named, zero-copy value a function receives through its bundle, such as x, y or u. A state view is a reconstruction of a store. An isbits state view materializes in the caller's frame for the duration of the call, and is value-identical on re-materialization within a sweep.

Evaluation and scheduling

algebraic loop — a genuine cycle in the instantaneous dependency graph. It is a build error whose diagnostic names the loop in slash form. The author breaks it with inserted dynamics, a UnitDelay, which samples the signal on the discrete tier, or restructuring. Not to be confused with an artificial loop, port-level acyclic but stage-level cyclic.

execution order — the order in which the stage functions run, fixed once at build time from wiring edges plus intra-component feedthrough. All stage-1 functions run in any order, then stage 2 in topological order, then x_deriv. Outputs carries it. The loop runs it as a flat list of (component, stage) entries.

flow / RHS — x_deriv, the continuous derivative function, f in the spec's formulas. Evaluating the RHS means running the whole sweep, since x_deriv reads the fresh table. There is no incremental x_deriv-only re-evaluation.

frame — one iteration of the loop (drain, integrate, boundary sequence, publication). It is the unit step! counts and the trace's ordinal key. Its start is its frame top, where the drain runs. Distinct from a boundary, and from the kinematic reference frames of the aircraft domain, which always appear compounded ("the b frame").

fused idiom — compute each law once, in a stage, publish it as a port, and let x_deriv or s_update copy it from y. The interfaces reward one source of truth rather than make duplication unwritable.

hand-down — the component's own stage-1 ports, which y_direct receives beside the wired inputs, as y_x, or y_s on the discrete tier. A shared intermediate is thereby computed once in stage 1 and read in stage 2, never re-derived.

hop / dead hop — a step of a cycle through one member, from the face one wire enters to the port the next wire leaves. It holds iff the member's stage-2 function routes that face to that port, and is dead otherwise. A loop is artificial iff every cycle crosses a dead hop.

projection — the optional per-component hook x ← x_projection(x). It runs in the only two positions in the boundary sequence between a state write and its decode: after integration, and after a handler's x-reset. It is the cheap end of geometric integration's projection methods.

sweep — one pass through the execution order, in one of two variants compiled from one list. The interior sweep, which RK stages and trial evaluations run, walks continuous entries only. The boundary sweep walks the full list, gating in due discrete entries. The arrival sweep closes an integration step, before the boundary sweep refreshes any discrete cell.

Time and events

anchor — the exact (T, τ) pair an Absolute entry establishes: period and offset in rational seconds. It severs its subtree from the enclosing scope's grid. Anchor 0 is the base grid itself. Anchors join the deployment constraint pool, and relative declarations below one compose against it exactly as against the root grid.

boundary — a published consistency point, where the boundary's macro-sequence completes and a snapshot goes out. Every grid point is a boundary. A localized event time t* and boundary zero are boundaries but not frame tops. The structural sense, a component's boundary and its boundary declarations, is ordinary English, never linked here.

boundary-detected — the detection policy a Bool-returning guard declares. The framework checks the guard for a not-holding → holding edge at boundaries only and never root-finds it. The policy is exact for guards over modes, root inputs and held discrete outputs alone. Those predicates cannot cross between boundaries.

boundary sequence / macro-sequence — what the framework runs at each boundary. It integrates, projects, iterates boundary sweep, guards and handlers to quiescence under the firing budget, then runs all due s_update calls and the logging and I/O staging. Boundary zero is the same sequence with an empty integrate.

chattering / localization budget — the bounded per-frame localization allowance, localization_budget, a deployment keyword defaulting to 8. Exhaustion degrades rather than throws. Localization stops for the rest of the frame, and further crossings fire at the next boundary, under a ChatteringBudget warning naming the event.

Δt_base — the base tick period, an integer multiple N_base·h of the continuous step. It is bound at the Deployment constructor from one of three sources: an explicit keyword, N_base·h, or derivation from the constraint pool (fully anchored models only). Every discrete component's period is an integer multiple of it.

due — a discrete component is due at a boundary when its (D, Φ) pair admits that boundary's tick index, (tick − Φ) % D == 0. A due component runs its stages in the boundary sweep and its s_update after quiescence. The due set is fixed for the boundary's event iteration and is given per kind of boundary.

edge semantics / holding — an event fires on a transition of its predicate from not-holding to holding, never on a bare sign change. The opposite crossing direction is declared as a second event with the negated guard.

firing budget — the rule bounding the boundary event iteration. Each declared event fires at most firing_budget times per boundary. That is a deployment keyword, an integer ≥ 1 that defaults to 4. The budget lets a re-enabled event fire at its true boundary, against a fresh sweep. Exhaustion drops the event's further edges there under a FiringBudget warning.

guard — the declared function that defines an event's predicate. It pairs with a handler in the ordered, named state_events collection. Its return type declares its detection policy. A Bool guard is boundary-detected, and a guard returning the nominal scalar is localized.

harmonic grid — the rule that every discrete period is an integer multiple of Δt_base, with Δt_base itself an integer multiple of h. Ticks therefore land only on step boundaries. Grid times are indexed from the frame count, never accumulated. Every anchor period and offset must be an integer multiple of Δt_base too.

input epoch — a maximal span of constant root inputs, delimited by the frame-top drains. Within an epoch a guard changes only through the trajectory. At a seam it can jump without crossing. The θ = 0 validation, a trial evaluation at xₙ under the frame's own u, tells a trajectory-caused edge from an epoch-caused one.

interpolant — the lazily built cubic Hermite continuous extension over the last completed step. Localization trial evaluations read the states they sweep from it. It is built only after the θ = 0 validation confirms an in-frame crossing, and invalidated at t*, where the handlers have made it a lie.

localized — the detection policy a sign-form guard declares. The crossing instant is bracketed by derivative-free root-finding over trial sweeps of interpolated states, to a bracket narrower than localization_tol · h (a deployment keyword, default 1e-6). Only the sign form can declare it, since the Bool form offers no root to bracket. It runs identically paced or unpaced.

pacing / pacer debt — the pacer inserts waits between completed frames and never alters the boundary sequence. A frame exceeding its wall budget leaves debt that later frames repay. Excess debt is forgiven by re-anchor plus warning.

phase (Φ) — a schedule's offset against its grid, in scope ticks for Relative(K, Φ) and in rational seconds for Absolute(q, τ). It is compiled to base ticks with 0 ≤ Φ < D by construction. The boundary gate is (tick − Φ) % D == 0, and a phase shifts firing instants, never the period.

predicate — what a guard defines: a Bool-valued form, or the sign of a continuous function, which holds when the function's value σ satisfies σ ≥ 0. Not to be confused with the condition, the value that sets a build's state. The device loop's running check and structural conformance predicates are distinct usages, never linked here.

prior — each event's stored sample of its predicate at the previous boundary's quiescence. It is always an honest observation, never a manufactured one. It is detection bookkeeping, absent from every state store, though a checkpoint carries it. A boundary's first round tests edges against it. Boundary zero sets every prior to not-holding.

quiescence — the fixed point of the boundary event phase. Event rounds, each a pass of sweep, guard checks and handlers, iterate until a round fires nothing. After that the priors are updated and due s_update calls run. No round before the last is published.

remainder step — the integration from t* to the original grid target after a localized event, with h′ derived at use. Guards are re-checked on it under the localization budget.

schedule / Schedule — the typed tick timing the Deployment carries. The Deployment constructor builds it, one row per discrete component carrying (D, Φ, Δt), plus the rate-scope rows. It is the single source of truth for Δt, and the substrate of the grid diagnostics and the hyperperiod chart.

state event — an event whose instant is unknown in advance and must be detected, declared as a StateEvent(guard, handler) pair under state_events. The criterion is detection versus scheduling, not which fields the guard reads, so a guard over an input is a state event too. It is detected either boundary-detected or localized.

t* — the localized event time: the holding endpoint of the root-finder's final bracket, structurally strictly later than tₙ. A full boundary runs there, but no ticks are due and no staged inputs are drained.

tick — an instant at which a discrete component's stages and update run, gated by counter modulo against the harmonic grid inside the boundary sweep. Different boundaries therefore run different subsets of the execution order. A base tick is a tick of the base grid, the instant every N_base frame tops; its period is Δt_base.

tick index — the count of base ticks, tick = k ÷ N_base at the frame top of frame k when k is a multiple of N_base. It is the index the boundary gate reads. An off-tick frame top and a t* boundary have none.

tier — the continuous or discrete side of the hybrid formalism, read off the state declaration every primitive makes, x_init or s_init, empty when stateless (DeclarationOnWrongTier names a violation). Bare "tier" means only this. The genericity classes are walked / pinned / exempt and the detection policies boundary-detected / localized.

time event — an event whose instant is known in advance and scheduled: the discrete tier's ticks, declared by sample_times and gated by the harmonic grid. The counterpart of a state event, which must instead be detected.

trial evaluation — a guard's value at one instant θ inside the step. At θ = 0 its state is xₙ, and elsewhere a point on the interpolant. It writes that state into the buffer and runs the interior sweep, so discrete cells hold their tick values.

Build pipeline

activation — the build's typed products at a given scalar type T. It re-types the cells and the state type by the leaf walk, lays out the buffers, re-invokes the workspace allocators and re-runs the probe chain. The nominal Float64 activation is the nominal evaluation's product. Any other is derived from it on request.

always-on conformance check — the probe's comparison left permanently in place. It holds each probed function's return to that function's predicate, a stage's to its cells' types, with fields paired by name. For a stage it is decided when the table write's method is generated over both types, so a conformant return generates no check instruction.

Build — the artifact build(world) produces, bundling the three steps' products. They are Structure, Outputs, Events, the activations keyed by scalar type, and warnings. It is the inspectable contract of the instantiation. attach! validates against it. Replay's fingerprint check, the ignore list and condition resolution read it too.

chunking — splitting a large phase body's entry tuple into statically typed chunks behind non-inlined function barriers. Each barrier takes its chunk by reference, and the event set's projection, guard and handler walks chunk the same way. It is the implementation's only representation freedom, and it converts compile cost from superlinear in body size to linear in entry count.

Deployment — the artifact the grid parameters fix: the build plus h, N_base, Δt_base, the algorithm and the three event parameters, carrying the Schedule, the grid diagnostics and its own warnings. It is scalar-free, it compares as a value, and a Model materializes it at a scalar type.

Events — a product of the nominal evaluation, built last, after the nominal stage probes. It holds per component the event names, their detection policies and the bundle names. It is separate from Outputs because a consumer of the execution order should not carry the event tables.

executable set — the function set an activation can actually run, hence exactly what it probes. A Dual activation sees only the continuous output stages and x_deriv, never the discrete stages, s_update, guards or handlers.

executor — the compiled form of the stage execution order: a concretely typed tuple of entries over statically typed cell storage, traversed by a compile-time-unrolled walk, with code-selecting facts in type parameters and plain data in fields.

leaf walk — the framework's derivation of per-activation types from a declared nominal type. Float64 leaves and Float64 type parameters follow the activation scalar, a Pinned{P} leaf yields P, and everything else pins. It applies to the type derived from x_init and to a continuous primitive's contracts alike. m_init, s_init and the discrete tier's contracts pin wholesale.

lens — the compiled navigation step of a condition entry. Its tree position tuple is lifted to a type parameter, giving type-stable access to the authored value at apply time.

measurement seam / phase bodies — phase_bodies(sim) returns the compiled bodies of the nominal activation bound over the simulation's own buffers. They are rhs, sweep_1, sweep_2 and ticks, plus per-event guards and handlers and per-component x_projection. Its one promise is identity with what the loop runs, which is what makes the allocation assertions honest.

Model — a deployment materialized at one scalar type. It holds the deployment, its executor, its status and its diagnostic cell. A Simulation runs only a Model{Float64}, and claims it at construction. A Model at another scalar is a service's scratch. Its entry points are listed under "Deployment and the model".

nominal — the Float64 activation, and of a declaration its Float64 face (for a continuous producer's output declaration, its evaluation at Float64). It is the only activation that runs in real time, and the one where the conformance check demands exact type match. The nominal evaluation probes every user function and returns Outputs, Events and the nominal activation.

Outputs — the nominal evaluation's product: per component the output port names each stage produces, and the execution order over the components. The feedthrough graph the order was computed over is derived from the Structure's connections and the stage-2 names where it is shown, never carried.

probe — the build's evaluation of a user function with real values, checking shape and type conformance. The nominal evaluation probes every user function once, at the initial state, so probes see only its branch. The probe chain runs the probes in topological order, each consumer on its producers' returns. Other activations re-run it over their executable sets.

probe value / input synthesis — the fabricated values a build-time probe runs on. probe_value(::Type) synthesizes them at the one kind of terminal with no producer, root inputs (zero(T)/false/first enum/T(), overridable). From there they flow the probe chain as the probed stages' own returns. They are strictly probe-scoped, never an initial root-input value, and a structural barrier keeps the two apart.

ProbeDual — the framework's public canonical concrete probe scalar (ForwardDiff.Dual{ProbeTag, Float64, 1}), which keys the CI activation pinning walked-leaf genericity. Its width is arbitrary, since what CI pins is genericity, not a particular Jacobian.

schema vs. layout — the two lookup families the Build supplies to condition resolution. Schema is the evaluated declarations, the authority on whether you may write this field and at what leaf type. Layout is where it physically lives (buffer ranges, store and root-input indices).

shadowing check — the check the structural walk runs on every component before its class is read. It looks in the component's parent module for a binding of a declaration name. One distinct from the framework's function throws DeclarationShadowed alone, naming the module, the foreign names and the missing import.

Structure — the structure step's product, everything the instance alone fixes. It holds the components and tiers, one row per assembly with its children and wires, the root inputs, the rate chains and the scope triples. The face table and each face's routing chain are functions over its wires. Nothing in it depends on a scalar type.

walked / pinned / exempt — the eltype-genericity classes. Walked payload/value types follow the activation scalar, a pinned entry keeps its declared type under every activation, and the discrete side is exempt. One leaf walk reads a continuous primitive's state and contracts alike. A contract leaf opts out of walking with the Pinned{P} marker.

Runtime periphery

bad datum — a datum unmappable for environmental reasons (truncated datagram, malformed JSON, out-of-range field). It is tolerated in the loop body: catch, stage nothing, report!(handle, MalformedDatum(cause)), continue. Any other exception propagates and becomes DeviceCrash. The classification is the device author's.

batch — a device's staged set of face ⇒ value writes, coalesced in its staging cell and applied whole at the next drain. The word means only this. Error reporting collects.

binding — the value passed at attach! that makes a device framework-legible. It subtypes AbstractBinding and declares its sides by the Bool traits is_input and is_output, false by default on the root. Attach checks its enumeration methods, claims and reads, against those traits. Every input-side binding stakes a claim, returned or greedy.

boundary counter — the loop's monotonic count of published boundaries, the fact the wait predicate tests, never reset across trajectories. It is incremented after the latest release-store, so a waking waiter can never see a stale snapshot. Distinct from the published-boundary ordinal a snapshot carries, which counts a trajectory's publications from 0 at boundary zero.

calling task — the task that invoked run! or replay!. It runs the loop itself, and every device runs on a spawned task.

claim — the set of faces a device may write. It is registered at attach, either returned by its binding's claims or computed as the unclaimed complement under is_greedy, and released at detach. Claiming an already-claimed face is an attach-time error (ClaimConflict), and a broad claim costs GUI liveness.

coalescing — the CAS merge keeping one pending batch per device. Untouched faces survive, and re-staged faces take the newest level (the per-face ZOH). Its outbound mirror is newest-wins snapshot delivery.

control plane — the separate few-word atomic surface carrying pause, pace, margin, stop and the other fields of Control. The loop consults it at frame top, so a change during a wait lands at the next one. A run's outcome belongs to the Run, not to it. It is structurally not staging, since a paused loop drains nothing.

derived liveness — the rule that a GUI widget is live iff its port's feed chain terminates in a root input inside the GUI's own claim in the run's frozen surface partition. It is baked once at run start, with no per-port "GUI-controlled" marking anywhere.

device — any attached participant in the periphery: a subtype of AbstractDevice under one authoring contract (a mandatory loop, and optional init!, shutdown! and unblock! hooks) and one handle. Input-only and output-only are degenerate uses, and the GUI is an ordinary device.

diagnostic cell — the per-writer cell each rostered device, the harness writer, the loop itself and the Model own for runtime diagnostics and liveness. It holds a bounded ring (capacity 16) of diagnostic values, per-kind suppressed counts and an atomic heartbeat timestamp. The loop takes it at the frame-top drain and freezes it into the published framework status.

door — an entry point that builds a run. There are four, init!, overlay!, restore! and replay!.

drain — the single point at the top of each frame where the loop takes each staging cell by atomicswap and applies it through the attach-compiled scatter, in attachment order. It never runs at a t* boundary, and under the roster freeze it performs no checks at all. The diagnostic cells are taken at the same point.

framework status — the concrete frozen value each snapshot carries beside the signal table. It holds the pacer diagnostics plus, per writer, the diagnostics the frame's drain took (recent), the counts the ring refused (suppressed), the loop's cumulative per-writer × per-kind counters copied in (totals) and the liveness timestamp.

greedy claim — the claim a binding declaring is_greedy receives: the unclaimed complement computed by the framework at attach instead of returned by claims, ordinary in every respect afterwards. An empty remainder is legal and reported (EmptyGreedyClaim), and the standard GUI binding is its instance.

harness cell — the always-present staging cell of the harness writer, written by stage!(sim, "face" => value, …) from any task, the calling task included. Its batches are ordinary, traced and surface-checked, and drained last by convention.

harness writer — the framework-owned write path stage!(sim, …), open to any task, with its cell; the design's sole derived surface. That surface is the unclaimed complement, the faces no rostered device claims, recomputed at every stopped-sim roster change. A write to a claimed face is ClaimedFaceEntry.

heartbeat — the atomic timestamp field of a device's diagnostic cell, stored on every loop pass from inside the handle primitives. The loop acquire-loads it at publication. A live device is one whose heartbeat is recent, read against the 2 s staleness threshold. It is a field, not a diagnostic kind.

inspection read / integration read — the two reads a binding chooses between. A deep path is an inspection read, with zero promises, right for looking at this build. An exported output face, read with get_face, is an integration read, curated and meaning-stable under substitution, right for consumers that outlive the build.

latest — the @atomic reference a published snapshot is release-stored into and readers acquire-load. latest(sim) hands the calling task the same immutable value a device handle gets.

levels doctrine — staged values are levels, never deltas, as in press_count = 17, never presses += 1. Levels are idempotent and survive coalescing. Button edges ride as monotonic press counters, and accumulators are model state.

next-snapshot wait — wait_next_snapshot(handle): the boundary counter plus one Threads.Condition under the canonical predicate loop (counter > last_seen && running). Newest wins, with no queues and no per-frame reset.

operator interrupt — Ctrl-C in an interactive session, read as a control-plane stop rather than a failure. Delivery is masked across the boundary macro-sequence and raised at a frame-top, wait or pause-block unmask point. The run then takes the ordinary graceful tail and ends stopped. Outside the REPL, SIGINT still kills the process.

orphaned claims — the claims of a device whose task died mid-run. Death is not detach. The roster entry and claims persist to run end, the root inputs hold their last-drained values, and the GUI renders the fact in the widget's source label. Recovery is between runs.

peek — the GUI display rule: a widget shows its own pending write if any, else the snapshot value. It reads its own cell only, which is what makes multi-click counting and paused editing correct.

periphery — everything outside the loop that exchanges data with it (GUI, input devices, network I/O, logging), together with the concurrency model binding them: staged writes inbound, snapshot reads outbound, control on its own surface.

roster — the list of attached device entries (binding, claims, stable device id, attachment order). It is a plain immutable value the loop reads once at run!, since attach!/detach! are stopped-sim operations.

Run — the state one run owns, a Simulation field beside the control plane. Its two const fields are the log and the trace. Its four writable ones are feed, termination and the trajectory's counters frame and boundary. The four doors, init!, overlay!, restore! and replay!, construct one, and closed(run) is termination !== nothing.

scenario component — the home of a sim-time script under the mid-run mutation doctrine: an ordinary periodic discrete component executed synchronously in the loop, deterministic paced or unpaced and replayed by recomputation. The clock is the criterion. Wall-clock interactions are devices.

should_abort — the per-attachment failure policy, an attach! keyword defaulting to false. Set, a device's departure (loop body returning, crash, or a failed init!) also requests a control-plane stop. Clear, the run continues with the device absent and its claims held to run end. It is never a device property.

snapshot — the immutable per-boundary publication: boundary-consistent signal table (root inputs included), t, frame index, boundary index and framework status. It deliberately carries no state stores, because the state trajectory is derived data. A run's terminal snapshot is its final one, and its status carries the run's final cumulative diagnostic counters.

stage-on-interaction — the GUI staging contract. Value widgets stage the new level on edit, and edge widgets stage on activation, as a level computed from the peek. Held buttons do not re-stage, and no widget stages per render pass.

StopPolicy — the immutable value one advance declares, t_end plus the requester paths it ignores. run!, replay! and step! build and validate it per call and pass it to the loop. Afterwards only the termination record keeps it. A stop through the stop word sits outside it.

stop word — the control plane's stop command, one atomic word holding its issuer. Not to be confused with a stop request, which the model publishes.

tail — the ordered shutdown sequence every stop takes. After the final snapshot it sets the sticky stopped status, wakes the framework's waits, calls unblock! and shutdown!, and joins device tasks under join_timeout. It has two entry points. Graceful entry follows a completed final boundary. Abnormal entry follows a discarded one and promotes the previous snapshot to final.

unattended run — a run with empty staging and no snapshot readers. It is the same loop, fully synchronous on the calling task, rethrowing after the shutdown tail so CI fails honestly.

write surface — the set of faces a writer's batch entries may reach. For a device it is the claim set, whether returned by claims or computed under is_greedy. For the harness writer it is the derived unclaimed complement. It is static per run and enforced entirely at staging, OutOfClaimEntry for a device and ClaimedFaceEntry for the harness.

Recording and replay

checkpoint — the Model's state at a frame top as one value, a ModelState, beside the run's frame index and boundary ordinal. checkpoint(model) reads the state alone and checkpoint(sim) the whole Checkpoint. restore! puts either back with no boundary zero. A checkpoint is not a condition and has no algebra.

decimation — the log's keep-every-kth retention policy, log_every. It is admissible on the log alone because the log is derived data. Every boundary still runs, publishes to live readers and enters the trace. When the log fills its log_max bound, the stride doubles. That progressive re-decimation keeps coverage global. Decimation is a view policy, never trajectory-determining.

fingerprint — the structural layout a checkpoint carries. It is the store layout and root-input faces the Build fixes, with what a copy by position relies on, each component's x type, every cell's address and type, and the event list in the order of the priors. Replay and restore! check it against the target simulation.

frame ordinal — the trace's key. Replay applies the recording's batches for frame k at frame k. That is exact because the frame sequence is itself deterministic under replay.

input mode — where the drain takes its batches from, read as mode(sim) off the run's feed: :live from the staging cells, :replay from a recording replay! attached. A replaying advance is bounded by the recording. The mode returns to :live when the recording's last frame is consumed, or when live! drops the remainder by hand.

log — the retained sequence of published snapshots (the same objects, no copies), with a plain kill switch and log_every decimation. It is derived data, recomputable from the trace by replay.

recorders — the trace and the log jointly. The four doors and a trim commit build them anew together, so they restart with the run they record.

replay — the ordinary loop with one substitution: the drain reads the trace by frame ordinal, after the trace's checkpoint is restored under the default form. It re-records, ends initialized, and validates the checkpoint's fingerprint (the structural layout) and its Deployment up front. The default form restores the clock with the rest of the state.

run metadata — the trace header's Deployment and t₀, hence Δt_base, h, N_base, the algorithm identifier, localization_tol, localization_budget and firing_budget. It carries no stop policy; each advance declares its own.

trace — the primary record of a session: the sequence of drained, device-tagged batches per frame, plus its header. It is on by default, because the log is recomputable from the trace and never the reverse.

trace header — the trace's fixed preamble, a checkpoint the door that builds the run writes once. init! takes it at the end of boundary zero, and overlay! after the overlaid state settles. It carries the run's Deployment and t₀ with the rest of the state. It holds no stop policy and no schema list.

trace record — the retained form of a drained batch, uniform for every writer: (position ⇒ value) pairs for the masked (touched) entries, converted at the drain against the trace's schemas list. Trace size therefore tracks information rather than surface width, and consumers meet one format and one replay path.

what-if replay — replaying a trace against the same structure with changed parameters: deterministic re-driving of the recorded inputs through a modified model, initialized by init! under the authored condition and fed by replay! with restore = false. It promises determinism but never bit-identical reproduction.

Stopped-sim services and the condition algebra

at / Scoped — the scoping combinator. at(prefix, node) stores a prefix beside a condition node and applies nothing. It also lifts whole TrimProblems and linearization tap sets. A read set keeps its prefixes as a chain and is not a condition node. An empty prefix is refused when at is called.

baseline — a full-coverage condition, such as an aircraft-shipped function (ready_for_taxi(ac), cold_and_dark(ac)) returns, layered under tweaks by override. It is also the baseline keyword trim! takes. Not to be confused with an event prior.

boundary zero — the initialization boundary: the ordinary macro-sequence with an empty integrate, run at t₀ once apply! has established the stores. The sequence is project → [sweep → guards → handlers]* → due s_update calls → first snapshot, after which init! takes the trace header.

combine — the symmetric, collision-intolerant combinator over condition nodes. A duplicate leaf is an error naming both origins, and blending a node with a bare NamedTuple is a directive error method.

component test rig — a one-child assembly exporting the child's entire input face set. It is the idiom for exercising a primitive that needs something wired beside it. An abstract entry is satisfied inside the rig by a concrete stub child wired to that face.

condition — the datum that says "set this build to this state". It is a path-addressed sparse overlay, on the declared defaults under init! and on a stopped run's stores under overlay!. It covers x, s and m fields plus root inputs by face, never outputs and never workspace. The stopped-sim services own the word. A guard defines a predicate.

design_world — the rig this design records for design-time work, aircraft + SimpleAtmosphere(wind = NoWind()) + HorizontalTerrain, which mounts an aircraft for trim and linearization. SimpleAtmosphere and NoWind are FlightPhysics' atmosphere types. "Aircraft as root" is the shallowest world, not a special case.

fragment — the leaf node of the condition algebra, built by set(; x, s, m, u). Its payloads speak only about the component at the authoring point (self-vocabulary), with addressing left entirely to at.

fragment tree — the inert, lazy composition of Fragment/Scoped/ Combined/override nodes. It is isbits but for the prefix strings, which are references to the author's literals, so rebuilding it per trim iteration allocates nothing and does no path work.

leaf address — the leaf argument of a selector, naming one leaf of a port value or one component of a state leaf. It is the field or face name followed by .name and [k] or [k,l] steps in any order, as in "pose.q_eb[2]" or "J[1,3]". A bare Symbol is the short form of a plain name.

mounting — relocating a whole problem or tap set with at(prefix, …). Each field is condition-producing (path-relative, post-composed), a read set carrying its mount chain, or path-free, so the service never knows where its paths sit. A read set's mount chain is the prefixes it is mounted under, root first. The read side rebases every selector to the root at resolution.

override — the ordered, asymmetric layering combinator. On a shared leaf the patch wins and the origin records both layers, while collisions within a layer remain errors. It is variadic.

read set — a Reads value, built by reads(name = selector, …), naming each selector it reads. It is trim's reads field and what series takes post-run. It carries its mount chain as data, and at prepends to that chain without making it a condition node. An output binding's read set is the labeled NamedTuple of selectors its reads returns.

root-input totality — the pre-write requirement that an application establishing a complete world over virgin stores (init!, trim setup, trim commit, linearization's operating condition under about) cover every root input. Conditions themselves are legitimately partial. A shortfall is UninitializedInputs, collected and declaration-ordered, leaving the simulation untouched.

selector (read-selector family) — the closed set of deferred reads get_state/get_deriv/get_output/get_input/get_face, each naming one leaf by its leaf address. Each resolves against a source. Table sources are a boundary snapshot or a service evaluation's scratch tables; the other source is the live stores.

service lifecycle — the Simulation states built / initialized / running / stopped / errored and each service's legality against them. A Model's own service forms gate instead on its statuses :built, :consistent and :inconsistent. A violation is ServiceLifecycle, and no service accepts an errored simulation.

stopped-sim — said of an operation legal only on a simulation that is not running. attach! and detach! are stopped-sim operations, legal while built, initialized or stopped. The stopped-sim services are init!, overlay!, trim!, linearize, checkpoint and restore!, and each one's inputs decide its legality among those states. An errored simulation refuses them all.

taps — the three selector lists (x, u, y), built by taps, declaring what linearization seeds and reports. Every tap names one scalar leaf. Resolution checks the selectors as ReadResolution and the tap set's own constraints as TapResolution. A tap set relocates via at.

TrimProblem — the closed nine-field value guess/lower/upper/condition/reads/residuals/tolerances/checks/check_tolerances. It is not a condition but an implicitly specified condition, solved as a square root-find over named residuals. Its commit is an init! of override(baseline, condition(d*)).

Error discipline and diagnostics

carrier exception — the single exception diagnostics travel in when thrown. DiagnosticError holds one diagnostic at a fail-fast site or the collection at a step barrier, and its type parameter tells which. StepError at the runtime catch site takes a single diagnostic over as its cause and carries the cause's type as its parameter. Diagnostics themselves are plain values.

descriptor — a serialized projection of a Build or a Deployment under a published, versioned format, for a client outside the process. descriptor renders it as plain data beside show's rendering to text. The artifact stays the truth, and a descriptor is one consumer's reading of it.

kind marker — the small object beside a leaf face's printed type in a descriptor, telling a client with no Julia what the type is: boolean, enum, symbol, integer, float, number, vector, struct or opaque, each with the fields it needs. Not a diagnostic's kind.

collect the checks, fail the evaluations fast — the reporting policy. Declarative passes over collected structure return their full violation list, while the first user-code exception aborts the phase. The build's steps are barriers, and a diagnostic kind's policy field spells the collecting case collected.

did-you-mean — the required shape of any name-shaped failure: the offending name plus the list-in-hand it should have matched, carried as payload rather than baked into message text.

error locality — the property the declaration layer buys. A mistake fails at the site of the mistake, not later and inside correct code. The five walkthroughs are its grounding cases, and they run as acceptance tests.

execution cursor — the executor's plain mutable field recording where execution stands in the compiled order. It holds three facts, the component by its index in the structure's component list, the function running, and the boundary phase. It costs one cheap store per dispatch, so a runtime failure gets its cursor frame without exception handlers in the hot path.

feedthrough tracer — the set-propagation instrument (global value-blind, or sampled primal-carrying) used to classify a rejected cycle as real or artificial. It is diagnostic only, never an input to the ordering.

kind — a diagnostic's identity in a closed, normatively enumerated set, with payload fields, owning section, severity, where it is raised and under which policy. Tests match on kind plus payload, never on message text. Not a component class or a function family.

payload — the structured data a diagnostic carries beside its kind: paths and names as strings (never instances or component types), expected/observed port types, the list-in-hand. Severity is the kind's, not the payload's.

requester roster — the build's list of stop requests, one Requester(path, port, reason) per StopFlag output port, in build order.

species — a StepError whose cause is a diagnostic, StepError{Kind} by type. It is what the catch site makes of a single-diagnostic DiagnosticError thrown inside the guarded sequence, under the species rule.

stop request / termination is a state — graceful termination is model state, never an exception. A model publishes a stop request as an output port of the framework enum StopFlag, anywhere in the tree. One reading STOP_REQUESTED ends the run unless the advance ignores it. StopRequest is the library spelling.

termination record — the stopped-sim value naming how the run ended. It holds the final boundary time, the StopPolicy of the terminating advance, a typed source with its payload, and the tail residue. A model-requested stop's payload is the requester's path, port and reason. It lives on the Run, never on the control plane.
